# 歩きと走りを見た目で区別する

追補：下記 revision-02 の走行には不自然な膝の折れと大き過ぎる腰の上下動があったため、走行だけを revision-05 に再制作した。現在の配信と検証は [RUN_REPAIR.md](RUN_REPAIR.md) を参照。下記は歩行の現行仕様と、最初の変更の履歴として残す。

2026-09-12、ユーザー指定「ちゃんと別にして。走るのはもっと走るっぽく、歩くのはちゃんと歩くっぽく」に対応。選択可能な7体の `Walk_Loop` と `Run_Loop` を作り直し、revision-02 を採用した。以前もクリップ選択は分かれていたが、今回の変更はクリップ内の足・骨盤・胸・腕の動作そのもの。

- 歩行：低い足の運び、直立に近い胸、控えめな腕振り、支持脚の交代。各脚の支持率60%で、常にどちらかの足が接地する。
- 走行：前傾した胸、深く曲げる肘と大きい腕振り、高い膝と踵の引きつけ、短い支持と浮遊。各脚の支持率36%。人間の腕振りは±39°、肘の曲げは約75°（歩行は±15°、約16°）。大猿の長い腕は別の曲げ量にした。
- 足の軌道を骨の実寸で解き、変形後の足裏を繰り返し測って位置を補正。足裏に3 mmの余裕を置き、フレーム間補間で床へ沈むことを防ぐ。

| 対象 | 歩行の周期 | 走行の周期 |
| --- | ---: | ---: |
| 男女のクロマニョン人・ネアンデルタール人、猫耳 | 1.10秒 | 0.72秒 |
| 砂耳の魔法使い | 0.90秒 | 0.60秒 |
| 巨腕の大猿 | 1.20秒 | 0.76秒 |

歩幅は実測脚長の1.25倍／3.15倍、足の持ち上げは脚長の6%／48%。周期と歩幅から素材の移動速度を再計算し、既存の再生倍率上限（歩行1.35、走行1.5）を使う。ゲーム上の移動速度は従来どおり。とくに脚の短い魔法使いと大猿では、速いゲーム移動に合わせるための足滑りが残る。足滑りをなくすために動きを早回ししたり、ゲーム速度を下げたりはしていない。

歩行と走行を混ぜる既存の0.16秒の切り替えでは、途中の補間姿勢に足先の一時的な沈みが残る（5位相×往復を120 Hzで追加測定し、最大約4.8 cm、魔法使いは約5.5 mm）。上記の接地保証は各クリップの安定再生時の測定であり、足を固定する実行時IKは追加していない。

## 制作と保持

制作はCodexによる手付けの推定動作。モーションキャプチャ、生成動画からの抽出、実在動物の科学的再現ではない。既存のTRELLIS由来の配信GLBを出発点とし、形状・ウェイト・骨階層・材質・テクスチャを保持した。`CREATURE_MOTION_GUIDE.md` の接地・体格・ループの基準を適用した。参照先の隣接 `threed-model-creation` リポジトリはこの端末に存在しなかったため、ゲーム内に保存済みの制作手順と既存の足裏検証コードを使用した。

基準は各モデルの `model-downed-r01.glb`。7体とも原バイナリ全体を接頭部分に残し、歩行・走行だけ新しい60 Hz相当のキーを追加した（整数フレーム数に丸めるため59.7〜60.5 Hz）。攻撃・待機・作業・倒れる等、ほかのクリップはJSONと参照バッファをそのまま保持する。モデル寸法、物理・戦闘、ジャンプ・騎乗・肩乗りの制御は変更していない。旧GLBと不採用revision-01は保持する。

- 正本スクリプト：`scripts/build-player-gaits.mjs`
- 採用：`scripts/adopt-player-gaits.mjs revision-02`
- 変更前manifest：`assets/player-gaits/source-manifests/`
- 候補と基準GLB：`output/player-gaits/{baseline,revision-01,revision-02}/`
- 配信URL・SHA-256：`assets/player-gaits/adoption.json`
- 配信名：各モデルの `model-gaits-r02.glb`

revision-01の目視で歩行の膝の曲げと上下動が大きかったため、revision-02は歩幅・足上げを減らし、支持脚を伸ばした。足裏の検査点を増やして女性の靴底の約9 mmの沈みも修正した。revision-01の検証では小さい魔法使いにも8 mm固定の浮遊判定を使っていたため、最終検証は足裏の余裕3 mm＋身長の0.4%を浮遊判定に使う。

## 検証

`scripts/verify-player-gaits.mjs revision-02` は最終GLBを120 Hzで読み直し、原バッファ・メッシュ・骨・他クリップの保持、スキン後の足裏、肘・膝の角度、ループ境界を検査する。全7体合格。測定した最低足裏高さは2.07〜2.98 mm、ループの表面誤差は最大0.00000031 m。歩行の浮遊率0%、走行は約15〜26%。詳細は `validation.json`。

実Chromeの `scripts/qa-player-gaits-review.mjs revision-02` で、7体×5方向×歩行・走行の6時刻を画像化し、30 Hzの120時刻を左右比較動画として保存した。保存先は `output/playwright/player-gaits/revision-02/`。各体の接地・腕・足・輪郭を横と斜めを中心に目視した。動画は最終GLBの実ブラウザー再読込を元にしている。MediaRecorderのWebMは描画待ちによる可変フレームレートだったため、共有用MP4はFFmpegで作成した時刻列の4秒へ時間を正規化し、30 fps・120フレームへ変換した。元WebMも保持し、入力の時間・フレーム数は `video-encoding.json` に記録した。

`tests/player-gaits.test.mjs` は7体の配信中GLBを直接読み、実際の肘の角度と足の上下幅が歩行／走行で異なること、および切り替えと停止を確認する。既存の動作混合と倒れた状態からの復帰の検査を含め26件合格。

全テスト538件、TypeScript検査、276個のJavaScript構文検査、依存境界検査も合格。通常3000番の配信manifestが新しいGLBのURL・SHAを返すことを確認した。

実ゲーム検証は `scripts/qa-player-gaits-game.mjs` で合格。実Chrome2画面＋通信3人の5人接続で、7体それぞれの歩き→走り→歩きの21区間、相手画面への同期、停止、ジャンプ→待機、攻撃→待機を確認した。390×844／844×390、再読み込み→タイトルの「はじめる」→大猿での再開も通り、console／pageエラー0。最終結果は `game-qa.json` と `output/playwright/player-gaits/game/report.json`。検査ではプロフィールと草原の開始位置のみ準備し、操作と時刻は実キー・実時間を使用した。

QA作成途中の失敗は、現在と同じキャラクターの決定ボタンを押す、サーバー側の停止状態からキーボードの走行トグルを推定する、ジャンプ中のnullのAnimationActionを観測する、再開時に表示されないキャラクター選択ボタンを待つ、という検査スクリプト側の問題だった。観測処理と通常の再開手順に直して全区間を再実行した。ゲーム本体の切り替え・再開処理は変更していない。

未検証：物理コントローラー、実端末、今回の動作による坂・橋での足裏位置、全メッシュ間の自己交差、長時間負荷。展示パッケージ・PC2・公開デプロイは更新していない。
