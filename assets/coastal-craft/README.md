# 浜の貝と、石の刃

既存の三つの岸の湾へ加えた暮らしと道具の遊び。世界の作り直しは行わず、拡張済みの大陸・湾・三つの国・畑・釣りを引き継ぐ。計画は [COASTAL_CRAFT_PLAN.md](../../COASTAL_CRAFT_PLAN.md)。

## 遊び方

「もちもの」またはポーズメニューの「貝と石器の作り方」から、貝場・焚き火・貝塚・石器作業場へ歩ける。湾の案内にも入口を追加。

- 五つの浜で E／×を押し、止まって2.4秒で生の貝1個を採る。各貝場の在庫は共有12個、1分で1個戻る。
- 既存の焚き火で3秒焼く。焼いた貝を食べると元気が最大20回復し、貝殻1個が残る。
- 四つの集落の指定場所へ殻を持ち帰り、1回に最大10個積む。最初の1個で貝塚が現れ、12個・40個で段階的に大きくなる。場所に人や生き物がいる間は成長を待つ。
- 西の八つの露頭で黒曜石を採掘。四つの石器作業場で、原石2個を4秒削って刃1個を作る。打ち石として石1個が必要で、石は消費しない。
- 刃1個と木材1個を使い、木槍へ穂先を装着する。人間系4種の初期装備は先に何も付いていない木槍（威力15）。装着すると黒曜石の槍（威力30）に変わる。猫耳の刀と魔法使いの魔法は維持する。全員が貝採集と刃の製作に参加できる。

貝殻が満杯なら食料だけ失うことはない。作業中の移動、被弾、攻撃、画面離脱、メニュー、切断で未完成の作業は中止され、材料は手元に残る。完了時にも距離・遮蔽物・在庫・持ち物の空き・費用をサーバーで確認する。

## 状態と世界

貝塚は固定四か所。持ち寄りが増えても描画物と衝突物の数は増えない。新しい持ち物・槍先・貝場・貝塚・個人の作業実績を、既存の短時間復帰とexport/importへ保存する。旧データの欠けた項目は初期値で補う。通常のNodeディスク永続化を追加したものではない。

世界は8,192×4,096 m、湾は1,480×1,340 mを継続。人数の既定5人と世界の広さは独立しており、今回の共有在庫の競合も8人のコアで検査した。公開Cloudflareの設定変更は含まない。

研究と出典は [WORLD_SETTING_PLAN.md](../../WORLD_SETTING_PLAN.md) を参照。この湾の貝塚の位置・大きさ、年間を通じた供給と回復、レシピ、秒単位の加工、威力の数値は創作。年代や地域が特定された遺跡を再現したという主張はしない。

## 3D素材

貝と貝塚はimagegenの参照画像からローカルTRELLIS-2（1024・seed 42）で制作。原画像、背景除去画像、dense GLB/PLY、採用前後のrevision、スクリプト、処理ログ、7方向のneutral/clayの比較を保存した。今回のログに記録されたGPUはRTX 3070 Laptop 8 GB。TRELLISとBlenderの重い処理は直列。

木槍は既存の採用済み石槍の木の柄を残して石と巻き付けを除いた派生版。黒曜石の槍は同じ石槍の形状・UV・画像バッファを保った材質変更。刃は同じ穂先の取り出し。旧石槍の配信GLBとasset.jsonをsourceへ保存し、欠けている歴史的な原画像やdenseの存在を捏造しない。新しい人物モデルやリグは不要で、既存の握り位置と動作を使う。

| 素材 | 採用revision | 三角形数 | 用途 |
|---|---:|---:|---|
| cockle-shell | 02 | 35,645 | 在庫に対応する浜の貝 |
| shell-midden | 01 | 92,239 | 殻の量で大きくなる共有の貝塚 |
| wooden-spear | 02 | 2,837 | 人間4種の初期装備 |
| obsidian-spear | 01 | 5,679 | 装着後の槍 |

貝のrevision 01はUVの継ぎ目で軽量化が割れたため不採用。木槍のrevision 01は切断後の法線処理で裏面に隙間が出たため不採用。両方とも元の位置を結合してから処理し直し、失敗版を保持した。貝塚の殻の間の隙間と、既存の石刃の不規則な底辺は源形状の特徴として残す。

貝のgeometry/materialをインスタンスで共有。近隣65 mで表示し、未使用の地域素材は12秒後に解放する。石器台は既存の岩を共用。新しい可視プリミティブや読込失敗時の代替モデルは追加しない。

制作の正本として、五つのモデルの309ファイル（659,421,513 bytes）を隣の `threed-model-creation/models/` へ追加保存し、全SHAを照合した。既存ファイルの上書き・削除は0。[保管の検査](archive-qa.json)に保存先と各SHAを記録する。

Gitには原画像、制作スクリプト、採用GLB、QAとそのSHAを含める。大型の `models/*/work/` 中間出力はローカルと正本の保管庫に保持し、Gitの対象から外す。クリーンなcheckoutで中間候補との比較や再制作を行う場合は、保管庫から該当するworkを戻す。

## 検証

[配信GLB検査](delivery-qa.json)、[実ゲーム記録](game-qa/r01/report.json)、[6種類の人物と装備](appearance-qa/r02/report.json)を参照。全252テスト通過。実Chrome2画面と通信3人で5人を接続し、3,448観測で静物・海岸の衝突違反0、console/pageエラー0だった。

貝の採集→徒歩で持ち帰り→調理→食事→最初の貝塚は通常操作。後の成長確認用40個の殻、露頭・資源・作業場の間の開始位置、他の人物の装備確認用の刃と木材は明記したQA準備値で、実際の採集や徒歩の証拠に数えない。原石2・石1・木材1の採集自体と削り・装着は通常UIを通した。メニューによる加工中止と材料保持も確認。

390×844・844×390はブラウザーの寸法検査。実物のスマートフォンやコントローラーではない。Gamepad APIの×入力を模擬した。最初の素材読み込み中の8 FPSを含み、その後の今回の15点の記録中14点は60 FPSだった。常時60 FPS、大人数負荷、長期稼働を保証する測定ではない。

従来の全制作履歴検証は、旧 `output/model-generation/models/neanderthal-hunter/qa/adoption-review.json` などの欠落により未完了。今回の53配信GLBと新規候補のSHA照合は、この欠けた履歴を代替しない。

NPCの日課、国ごとの生活行動、追加作物、天候・海流、大人数負荷の検証は引き続き残る。今回の追加と全体ロードマップの完了を混同しない。
