# 三つの岸の湾：空と航路

2026-09-08。既存の丸木舟、五つの浜、湾奥の陸路に天候と海流による航路選びを追加。計画は [WEATHER_CURRENT_PLAN.md](../../WEATHER_CURRENT_PLAN.md)。実装・ローカル反映・実ブラウザー検証を完了。

## 遊び方

湾の画面の「空と航路」、または舟の操作欄の空模様を選ぶ。現在と次の空模様、切替までの秒数、流れの向きが分かる。上陸地を選ぶと、陸上では浜へ歩き、乗船中は浜の水際へ漕いで向かう。到着後は既存の乗降操作で上陸する。「湾の地図を見る」では流れの矢印を表示する。

凪では遠い浜へ渡りやすい。海風では流れに沿うと速く、逆らうと遅くなる。雨風では沖の移動が遅くなり、海霧では遠方が見えにくい。岸近く・湾奥では速度への影響が弱いので、集い場の浜を経由する道も使える。全ての天候で逆流に向かって前進できる。

漕ぐのをやめるとその場で留まる。メニュー、入力切れ、漁、空の舟を流さない。横流れを再現する物理ではなく、進む向きに応じた速度の補正。荷物、元気、畑には天候による追加の消費や損害を発生させない。

## 共有の仕組みと限界

- 既存の部屋の開始時刻から、180秒ごとの「凪→海風（東流）→雨風（東流）→海風（西流）→海霧（西流）→凪」を計算。最後と最初の凪は連続する。シーケンスは繰り返し、次の状態も共有する。
- 海岸の共通2m格子にある距離帯を使い、岸から4〜30mで徐々に影響を強める。湾奥から外湾に向かう強弱と、地域端の48mの移行帯を組み合わせる。実際の風波・潮汐の解析ではない。
- 全速で漕ぐ基準は通常4m/s、高速7m/sのまま。最大の流れは約0.9m/s、雨風の最大減速は28%。最終速度は基準の55〜125%以内。浅いスティック入力の倍率は既存処理が続けて適用する。
- 移動の確定、海岸・船同士の衝突、経路の終点、入力500msの期限はサーバーの既存処理を共用する。天候をクライアントから指定する操作はない。
- 天候は通常の小さい状態配信にも含める。開始時刻を既存export/importから復元するため新しい保存用タイマーは不要。切断中の乗り手は従来どおり乗船した安全な岸へ戻る。通常のNodeディスク永続化を追加したものではない。
- 空・光・霧と既存384粒子の材質を使い、雨を表示。海霧では霧の遠端が湾内で118mから66mになる。新規GLB・依存パッケージ・景観モデルは0。ほかの地域の固有表現は保持する。

これらの周期、流れ、舟の性能、予報、操船補助はすべて創作。[歴史的基礎](../../WORLD_SETTING_PLAN.md)にある水上移動の証拠を、実在の航路・舟の設計・定期海運の証拠と混同しない。Three.jsの霧の色・距離の更新は[公式資料](https://github.com/mrdoob/three.js/blob/dev/manual/pages/fog.html)を確認して実装した。

## 検証

再現用スクリプトは `scripts/qa-maritime.mjs`、回帰テストは `tests/maritime-weather.test.mjs`。位置、資材、時計などの準備値はブラウザー記録に明記する。物理コントローラー・物理スマートフォン・大人数負荷・長時間稼働・常時60FPSは今回の検証対象外。公開デプロイと料金変更は行わない。

世帯移住、複雑な政治、長期食料収支は残る改善。

全285テスト通過。実Chrome2画面＋通信3人、731観測で衝突違反・ブラウザーエラー0。波による減速と流れの速度差、5隻同期、対岸への上陸、漁、再読込、模擬Gamepad、狭い画面を検証した。初回に見つけた横はみ出しと、乗船位置補正時のカメラ追従不良を修正。最終のスクリーンショットではロード直後を除いて57〜60FPSを観測したが、継続的な性能測定ではない。詳細は [QA](qa-summary.json)、[ローカル反映](rollout/report.json)。
