# 世帯の旅と集い場での滞在

2026-09-08。計画は [HOUSEHOLD_JOURNEYS_PLAN.md](../../HOUSEHOLD_JOURNEYS_PLAN.md)。既存の住人8人・三つの国・集い場・地形を使い、共同生活の場を一時的に移す旅を追加する。

## 遊び方

「集落の人びと」または住人との会話から「世帯の旅」を開く。国の炉のそばで木材2・ベリー3・水1を渡すと、二人が炉に集まって出発する。一世帯につき一人が渡せばよい。地図の点と破線で現在地と残りの陸路を確認できる。

| 出身 | 世帯・住人 | 行き先と役割 |
| --- | --- | --- |
| 長い谷の国 | 谷道の世帯：ミラとトヴァン | 谷道から集い場へ。畑と狩り道具の手伝いを旅先でも受け付ける。 |
| 白い尾根の国 | 白石の世帯：エナとロク | 尾根の道から湾奥を回る。石と柄の手入れについて話せる。 |
| 葦の岸の国 | 葦辺の世帯：ネリとダロ | 東岸から湾奥を徒歩で回る。食事や浜の道具の手伝いがある。 |
| 多くの炉の集い場 | アルとセノ | 集い場に残り、従来の仕事と旅人の手伝いを続ける。 |

到着してから二日（実時間8分）滞在する。既存の訪問用天幕・作業場所・炉で四つの日課を送り、帰りは同じ道を歩く。帰着後は一日（4分）休む。空いている経路の検査では出発から到着まで谷約5分、尾根約13分、葦の岸約15分。これは待ち合わせ・混雑で延びる目安で、時計だけを進めても瞬間移動しない。

滞在中に二人のどちらかへ近づいて迎えると、ベリー・根菜・薬草の種を各1個受け取れる。各訪問につき各プレイヤー一回で、招待者以外、別の国、猫耳や魔法使いも参加できる。住人の従来の「今日の手伝い」は別枠のまま。依頼の材料・報酬は移動先でも変わらない。

## 共有と保存

- 移動と衝突は既存のサーバー処理。二人が約12m以上離れると先行者が待つ。会話・混雑が解消すると再開し、日付・季節の変更は道中の目的地を上書きしない。
- 材料、距離、遮蔽、作業中の可否、お礼の所持上限・重複をサーバーが検査。共有の畑・食料・資源を住人が自動で消費する処理は加えない。
- 世帯の段階・通過点・訪問回数・休息期限、住人の現在地、お迎え済みの進行を既存export/importへ含める。旧保存には自宅にいる三世帯を補い、遠方の不正な座標や無効な段階は採用しない。
- Nodeの短時間の再接続は従来どおり。通常のディスク永続化は追加しない。保存中に時間が過ぎても旅人は保存位置から歩き続ける。滞在期限を過ぎていた場合はそこから帰り支度に入る。
- 最大5人は現在の接続設定。世帯数・住人人口と結び付けず、8人のコアでも準備の重複・状態配信・保存を検証する。
- 8人の既存人物モデルと国の材質、既存の天幕を使う。新規GLB・依存パッケージ・メッシュ・テクスチャは0。遠くへ去った住人の描画は既存の距離制御・素材共有を使う。

## 歴史と創作

[調査した世界観](../../WORLD_SETTING_PLAN.md)にある移動・集まり・場所の再利用を発想の基礎とする。今回の三世帯は「同じ炉を分かつ生活のまとまり」という創作で、核家族・婚姻・血縁・性別による分業を推定したものではない。人物名、組合せ、相談の仕組み、行先、贈り物、日課と短い周期も創作。世界の住民がこの8人だけという設定ではなく、既存住人による訪問の一例である。

永住・出生・人口増加・複雑な政治・長期食料収支・住人の操船は残る改善。公開デプロイと料金変更は含まない。

## 検証

回帰検査は `tests/household-journeys.test.mjs`、実Chromeの再現は `scripts/qa-household-journeys.mjs`。三つの全往復と滞在中の全日課は地形・人物衝突を有効にしたシミュレーションで確認する。実Chromeでは通常の旅支度・出発を操作し、最後の経路区間だけを準備位置として到着・お迎えを検査する。滞在終了の時計変更と近接用の位置・材料も記録し、全経路の実ブラウザー歩行と混同しない。

全294テストと最終の住人10テストを通過。実Chrome2画面＋通信3人の最終341観測で、衝突違反・ブラウザーエラー0。初回に見つけた会話直後の手伝いの取りこぼしは、既存の連続操作制限に合わせて500ms待機する表示で修正した。地図の世帯名も明るい文字と輪郭で読みやすくした。

通常3000番は直前の部屋0・参加者0を確認して更新し、8配信モジュールの一致と通常の移動・画面導線を実Chromeで再確認。反映確認用の17文字の部屋コードをブラウザーが16文字へ短縮し、監視側だけ別室に入るQAスクリプトの問題も修正した。ゲームの経路障害とは区別する。

物理コントローラー・物理スマートフォン・大人数負荷・長時間稼働・常時60FPSは未検証。スクリーンショット時のFPSは20〜60で、読込や画面寸法変更を含む点の観測。継続的な計測ではない。実測と最終結果は [QA](qa-summary.json)、[ローカル反映](rollout/report.json) を参照。
