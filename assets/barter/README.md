# 集い場での物々交換

既存の採集・農耕・石器製作・共同食料置き場から続く、プレイヤー同士の交換。計画を先に [BARTER_PLAN.md](../../BARTER_PLAN.md) に記録した。国・種族による制限はなく、人間の木槍／黒曜石の槍、猫耳の刀、魔法使いの魔法を保持する。

## 遊び方

1. 二人で多くの炉の集い場へ来て、互いに4m以内で止まる。
2. 「三つの岸の湾」→「旅人と物々交換」で相手を選び、誘う。相手は同じ案内を開いて参加する。誘いはHUDに表示され、相手の画面を勝手に開かない。
3. それぞれ一種類・1〜20個を提示し、自分が渡す品物と受け取る品物を確認する。
4. 二人とも「この内容で交換する」を選ぶと、その場で受け渡す。提示を変えた時は二人とも確認し直す。同意済みの内容を変える時は「同意を取り消して見直す」を選ぶ。

対象は木材・石・黒曜石・未装着の黒曜石の刃・三種の種・食料・香草・貝殻の計19種類。装備と水袋は対象にしない。双方が集い場中心から22m以内、地上で停止し、相手との間が遮られていないことが必要。誘いから120秒、一人一件、誘い直しは5秒待つ。

未成立の品物は手元に残る。中止・移動・別の作業・被弾・切断・画面を離れる操作で交換を取り消す。成立・中止の結果は10秒表示する。双方の同意を得た交換は、共同食料置き場の一日3個の受け取りとは別で、採掘・収穫実績を増やさない。受け取った食料は食事や持ち寄りへ、刃は既存の作業場で槍先に使える。

## 同期と保存

サーバーが交換IDと内容の版、参加者、距離、遮蔽、作業、期限、材料、所持上限99を検査する。古い同意・第三者・二重成立を拒否し、成立直前に双方の持ち物を再確認して一度に更新する。同じ品同士は差し引き後の所持数で上限を確認する。

交換の誘い・提示・同意は部屋内だけの一時状態。保存と復帰には成立済みの持ち物だけを含める。旧保存へ未成立の交換を足さず、既存の資源・畑・貝塚・食料置き場・住人・世帯を保持する。既定5人の接続上限と交換の組数は独立する。

## 創作と範囲

場所、同意の手順、交換できる品の分類、個数と時間はゲームの創作。非在地の石が必ず交易によって運ばれたとはしない。考古学の背景と直接調達・移動などの解釈は [世界設定計画](../../WORLD_SETTING_PLAN.md) に保持する。

既存の炉と天幕を使い、新規GLB・可視プリミティブ・テクスチャ・依存パッケージは0。市場建築・貨幣・倉庫を追加しない。腐敗、住人の自動消費、長期食料収支、人口変化、複雑な政治は今後の別の改善。通常Nodeのディスク永続化、公開デプロイ、料金変更は追加しない。

## 検証記録

サーバーの検証は [barter.test.mjs](../../tests/barter.test.mjs)、実Chromeの再現は [qa-barter.mjs](../../scripts/qa-barter.mjs)。`GAME_QA_BUILD` で分離したビルドを指定でき、2画面と通信3人の専用部屋を使う。近接位置、交換する品物、最初の元気は明示的な準備値で、採集や調理を実際に行った証拠とは区別する。Gamepad API入力と画面離脱イベントは模擬する。

結果は `qa-summary.json`、既存モデルの照合は `assets-qa.json`、ローカル反映は `rollout.json` に記録する。物理コントローラー・物理端末・大人数負荷・長時間稼働・常時60FPSは未検証。
