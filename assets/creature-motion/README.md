# 既存キャラクターの動作見直し

2026-09-09。ユーザー指定の [Lystrosaurus in Motion](https://lystrosaurus-motion-study.pages.dev/) と [紹介投稿](https://x.com/shinboson/status/2096390580594995519) を踏まえ、既存8モデルの全65クリップ、6外見のジャンプ・騎乗・乗船姿勢、動作の切替を見直した。採用版は **revision-04**。制作基準は [CREATURE_MOTION_GUIDE.md](../../CREATURE_MOTION_GUIDE.md)。

## 対象と結果

| 対象 | 既存クリップ数 | 今回の変更 |
| --- | ---: | --- |
| クロマニョン女性・男性 | 各9 | 各外見の歩行・走行と共通の動作切替 |
| ネアンデルタール女性・男性 | 各9 | 各外見の歩行・走行と共通の動作切替 |
| 猫耳のクノイチ | 9 | 脚・靴の実寸に合わせた歩行・走行と動作切替 |
| 砂耳の魔法使い | 9 | 短い脚と足裏に合わせた歩行・走行と動作切替 |
| カラス人間 | 6 | 歩行・走行、移動と攻撃・被弾・死亡の切替 |
| マンモス（大小で共有） | 5 | 四脚の支持順序、歩行・走行と動作切替 |

人物は Idle / Walk / Run / Gather / Craft / Give / Eat / Wave / Attack、カラス人間は Idle / Walk / Run / Attack / Hit / Death、マンモスは Idle / Walk / Run / Graze / Death を確認。住人8人とオルも同じ人物素材・再生処理を使う。保管中の旧魔法使いは現行外見の対象外。

16個の歩行・走行クリップを修正し、他の49クリップは元のデータを保持した。ジャンプ・騎乗・乗船は既存の骨格を動かす実行時姿勢を保持し、6外見それぞれで形状と退出後の復元を確認した。

## 改善内容

- 支持中の足裏が後方へ進む速度と移動速度を合わせ、遊脚が前へ戻る軌跡を連続にした。骨の長さを保持した二関節IKで膝の曲がる向きを固定し、足裏のスキン変形も測って補正した。
- 足が届く範囲に合わせて骨盤の高さを滑らかに調整した。最初の候補の過度な中腰を採用せず、短い魔法使いには別の足の持ち上げ量を使った。
- マンモスは左後・左前・右後・右前の位相差を持たせ、重い四足として長めに支持する。元の鼻・耳・尾、人物の上体と腕の動きを継続した。
- 歩行と走行を切り替えても歩幅の周期を先頭へ戻さない。連続して動作を変えても混合する重みの合計を保ち、元の立ち姿が混ざる瞬間を防いだ。
- 新しい敵の単発動作には短い移行を設け、途中参加で時刻が進んでいる場合はサーバーの時刻へ直接合わせる。
- 焼き根・香草焼き根を実際に食べた時も、既存の Eat を再生する。

歩行周期・公称歩幅速度・攻撃の長さと命中時刻・移動速度・衝突・手動操作は保持した。参考作品の歩き方や生成動画をコピーしたものではなく、現在の骨格から手作業で設計した動作である。

## 素材の保持と採用

配信されていたGLBを `output/creature-motion/baseline/<key>/` へ保存し、これを修正元とした。この端末には当時の生成ワークスペースの一部がなく、生成元ファイルを再取得したという扱いにはしない。

既存の頂点、ウェイト、骨格、UV、材質、画像、元のバイナリを保持し、歩行・走行のキーフレームを追加した。候補01〜04は別フォルダー。採用ファイルは `public/models/<key>/model-motion-r04.glb`。元の `model.glb` を含む59個のGLBはバイト単位で保持し、古いmanifestを持つ画面からも読み込める。

各manifestと一覧のURL・容量・SHA-256・制作記録を更新した。各モデルの採用記録は [models](models/)、全配信の照合結果は [delivery-validation.json](delivery-validation.json)、変更前のGLB一覧は [adoption.json](adoption.json)。通常3000番へクライアントと素材を反映し、PID30044の再起動・保存の再適用は行わない。再読込したゲームで新しい動作を使う。公開デプロイ・展示パッケージ更新は行っていない。

## 検証

- 最終GLBの構造・in-place・ループ・全クリップの時間、スキンウェイトとハッシュを確認。49クリップ、形状・材質・骨格と元のバイナリの一致を機械的に検査した。
- 足首を120 Hz、足裏と表面の分布サンプルを60 Hzで測定した。結果は `output/creature-motion/revision-04/validation.json` と `skin-validation.json`。
- 全65クリップについて4方向×5姿勢の画像32枚と動画8本を記録。6外見×4種類の実行時姿勢も画像24枚・動画6本を記録し、体型・関節・衣装を画像で確認した。保存先は `output/playwright/creature-motion-20260909/exact-glb/revision-04/`。
- 分離版と採用後の通常ファイルの全364テストが通過。動作の急な切替、周期の保持、食事判定の新規5件に加え、6外見の最終スキンでジャンプ・乗船・マンモス座面への追従と姿勢復元を確認した。通常版の結果は `output/creature-motion/final-tests.txt`。型検査、190 JS構文、依存境界も通過した。
- 実ブラウザー2画面＋WebSocket3人の5人部屋で、歩行・走行・停止・ジャンプ・着地・攻撃・手振りと騎乗の Idle / Move を両画面で観測した。ジャンプの高さは両画面で約1m。再読込で復帰し、乗車・移動・降車と降車後のジャンプを確認した。
- 通常3000番の別の確認用部屋を通常の旅支度から開始し、ジャンプと槍の攻撃、採用SHAの表示を確認した。ブラウザーエラー0。全8GLB・各manifest・一覧・3配信モジュールが一致した記録は [live-validation.json](live-validation.json)。

入力の連続操作は確認専用画面からの模擬キーボード入力。外見の初期値とマンモス近接の位置・待機状態は準備値で、通常の長距離移動や物理コントローラーの実績と区別する。修正前の確認用入力がイベントの届かない場所へ送られた回は採用せず、ゲームのcanvasへ届く入力で再確認した。2画面の連続動作の最終記録は `game/cycle-a.json`・`cycle-b.json`、騎乗は `game/riding-a.json`・`riding-b.json`（上記出力フォルダー内）。それぞれブラウザー例外0。

最初の分離プレビューで、候補を差し替える前から開いていた画面に旧manifestが残り、カラス人間のSHA照合に失敗した。再読込で解消を確認し、通常版では旧GLBを置き換えず別URLで採用する方式にした。

## 残る制約

足裏は表面を抽出したサンプル検査であり、全頂点・全姿勢の自己交差を保証しない。平地の基準でマンモス走行の足裏の沈みは約6.2cmから約1.5cmへ減ったがゼロではなく、人間側にも最大約8mmの残りがある。全指標が一律に改善したわけではなく、小さい魔法使いの走行の最大関節回転量は元より少し大きい。実寸に合う接地と画像上の姿勢を併せて採用した。

傾斜や段差へ足を個別に合わせる地形IK、指・顔・独立した衣服・毛の物理、耳や尾の骨を増やす改修は含めない。現在の骨格で表現できる二次動作を保持した。動画は30 fpsを要求して記録したが、実測のキャンバス更新頻度は記録JSONに残してあり、常時30/60 fpsの証明にはしない。全状態の坂・橋での実プレイ、狭い画面、物理タッチ端末・物理コントローラー・長時間負荷は今回未検証。

既存の `verify:assets` は、当初の生成画像・採用記録がこの端末にないため全制作系統の一括検査を完走できない。今回の配信8モデルは別の `verify-motion-delivery.mjs` で検査している。過去の制作記録は捏造せず、既存検査の狩猟追加時の比較も、その当時の保存済みGLBへ適用するよう更新した。

## 再現

```powershell
node scripts/revise-creature-motion.mjs revision-04
node scripts/verify-creature-motion.mjs revision-04
node scripts/verify-motion-skin.mjs revision-04
node scripts/build-motion-preview.mjs revision-04
node scripts/serve-motion-review.mjs 3016
node scripts/qa-creature-motion.mjs
node scripts/verify-motion-delivery.mjs
node scripts/verify-motion-live.mjs
```

GLB比較は `http://127.0.0.1:3016/`、実行時姿勢は `?runtime=1`。ゲーム確認は3017番の `?room=MOTION-QA&qa=a` と `qa=b` を別画面で開き、通常の旅支度を経て確認用ボタンを使う。確認用のコードは通常版へ配信しない。採用を再実行する `adopt-creature-motion.mjs` は、現在の配信が保存した元SHAまたは同じ採用SHAであることを確認してから書き込む。

作業終了時は比較ビューアー3016番・PID4168を保持。今回だけの確認サーバー3014・3015・3017番は停止した。通常3000番・PID30044の開始時刻は13:35:49のまま保持している。
