# 紫尾の巨獣・有角四足版

ユーザー指定の有角四足版を制作し、ゲームへ採用した。二本の角と四本の支持脚を
持つ新しい画像から、ローカル TRELLIS-2 で形状を復元した。

旧版の `public/models/violet-behemoth/model-r10.glb` とそれ以前の GLB は保存し、
四足版は別ファイル `public/models/violet-behemoth/model-quadruped-r04.glb` として、
同じゲーム内モデルキー `violet-behemoth` へ採用した。
現在の突進・噛みつき・尻尾回転・毒液、予備動作、威力、速度、射程上限、
通過後の減速停止、背後からの再認識を引き継いだ。

## 来歴

- 原画像：Codex 内蔵 imagegen。旧版の紫の巨獣の参照画像を入力し、
  四本の発達した脚と大きな二本の角を持つ別の体型を制作。
- 原画像・プロンプト：`source/reference-v1.png`、`source/prompt.txt`。
- 正本の制作フォルダー：`output/model-generation/models/violet-behemoth-quadruped/`。
- 候補は 1 体。失敗した処理と修正版は同じ候補の履歴として保持。
- 旧 GLB の SHA 一覧と採用前の設定：`baseline.json`、`retained-original/`。

## 検証・採用

採用版は candidate 01 / rig revision 04。SHA-256 は
`6dd28210973bdccc543c0e2805ced82c838b95df2535218a652fda8ca869aa55`。
15,320,936 bytes、47,789 三角形、28 骨、14 クリップ。
モデル全長6.003 m・幅3.445 m・角までの高さ3.119 m、表示倍率は従来の2.5。

### 形状と動作

1024 解像度、seed 42 の復元を387.84秒で完了。約29.9万三角形の復元から、
表面誤差を測って軽量化した。許容基準は双方向の95パーセンタイル3.74 mm、
最大18.7 mm。最初の1.8万・3万三角形案は基準を満たさず、4.8万案を採用。
UV と画像由来の皮膚・角・爪を保持し、非金属の材質と滑らかな法線を設定した。

前脚・後脚にそれぞれ上肢、下肢、足先の鎖を設けた。四本の足先を別々の IK で
接地させ、歩行は四拍、走行は対角の足が組になる速い足運び。
突進時は加速に伴って胴体から7節の尾へ波が伝わる。回転時は尾の節ごとに
26 msずつ遅らせ、終盤に減衰する揺り戻しを付けた。

突進は低く構えて一歩踏む `Roar`、回転は腰を落として尾を上げ逆向きに溜める
`Tremble`、噛みつきは `Gape`、毒液は胸が膨らみ首を引く `SpitWindup`。
`Spit` の口を実測し、発射位置を前方2.292789 m／高さ1.618924 mへ更新した。
実ゲームの発射144 msは制作クリップの0.18秒に対応する。滴は17時点の口の座標を
補間する。`shared/behemoth-mouth.mts` はこの測定値で、威力・速度・射程を変えない。

revision 01 の回転中心のずれと走行時間の丸めを直し、revision 03 で接地・変形検査が
通過した。映像確認で残った「死体が前脚に支えられる姿勢」を revision 04 で修正。
倒れる側の脚をたたみ、胴体を地面へ落ち着かせた。各版の GLB・Blend・ログは保持。

### 検証結果

- 最終 GLB を240 Hzで独立再生。全14クリップ合格、最低床上高さ0.475 mm、
  ループ終端の表面差0、ルートの移動0、スキン最大4影響・重み合計1。
- 予備動作は最低3本の足で支持し、突進・走行・回転も最低2本が接地。
  IKの届かない距離を埋める関節の平行移動は、採用版の全支持動作で0。
- 最終 GLB を読み直し、14クリップ×6方向×5時点の420画像と14本の動画を制作。
  MP4のサンプル表で30 fpsと全フレーム数を検査。ループの重複最終フレームは除外。
- 実Chrome2画面＋通信3人の5人接続で15項目・282観測、エラー0。
  突進、噛みつき、回転、毒液の命中と回避、通過後の減速、遠ざかる標的への突進、
  離脱と帰還、帰還後の背後から実Wキー歩行／実Fキー槍攻撃による再認識、
  再読込、390×844／844×390を確認。
- 全565テスト合格。初回は保存テスト1件が待機時間切れになり、保存13テストの
  単独再実行と、全件を並列度4にした再実行が通過した。型・strict、294 JS構文、
  依存境界も合格。
- 旧版を含む既存104 GLBをSHAで照合し、全て不変。通常3000番でも新モデルの
  マニフェストと口の座標モジュールの配信を確認した。

数値検査は平らな床。全メッシュの自己交差、坂・橋での四足の個別接地、
物理コントローラー、長時間負荷は未検証。公開デプロイ・展示／PC2の更新は行っていない。

### 2026-09-13：縄張りの巡回と紫色の強調

標的がいないと毎tick停止させていた処理を、`shared/behemoth-patrol.mts` の巡回へ変更。
7〜13m先の通行可能な地点を選び、最高1.05m/s、加速0.6m/s²、旋回上限0.7rad/sで
ゆっくり歩く。到着すると1.5〜3.3秒休止して次へ進み、帰還完了後も1.8秒で再開する。
中心位置は縄張り半径30mから体半径5.25mと余裕1mを引いた範囲に収め、実際の
地形・障害物・人物の衝突判定を使う。塞がれた行き先は再選択する。
巡回・休止より索敵と被弾反応を優先し、標的に気づくと巡回を中断して従来の攻撃に入る。
誰も接続していない部屋は従来どおり休止し、接続者が縄張りから離れている間は巡回する。

`src/behemoth-palette.ts` でテクスチャ中の皮膚の色を選択し、明暗と凹凸を残して
青紫を強める。角・牙・爪の暖色は残す。適用はこの敵のモデル読み込み時のみ。
GLB、埋め込みテクスチャ、骨格、14クリップ、攻撃設定は変更していない。
現行r04と旧5 GLBのSHAを確認し、通常3000番の巡回・材質JSと現行GLBも照合済み
（`patrol-purple-served.json`）。

検査は3分間×2刻み幅の巡回、縄張り内の体の収まり、緩やかな旋回、障害物での
再試行、背後の足音による中断、帰還後の再開。全572テスト、型・strict、296 JS構文、
依存境界を通過。既存の帰還テストは「帰還地点で永久に停止」から
「元の位置へ帰還してから巡回を再開」に期待値を更新した。

実Chrome2画面＋通信3人でも17項目・360観測が通過、エラー0。
全員が縄張り外にいる約40.5秒間に28.1m巡回し、全攻撃・毒の飛沫・回避・
通過停止・帰還後の背後からの実W歩行／実F攻撃・再読込を確認した。
毒液の検査は、画像保存中に短い飛沫を見逃した2回の失敗を受け、実際の
`PoisonEffects.update` を各フレームで観測する方式へ修正（172フレーム、最大67粒子）。
ゲーム側の毒液処理は変更していない。最終記録は `patrol-purple-game-qa.json`、
画像と全観測は `output/playwright/behemoth-patrol-purple-verified/`。
