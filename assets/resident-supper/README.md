# 住人が炉で分け合う夕食

既存の食料と住人の日課をつなぐ改善。先に [RESIDENT_SUPPER_PLAN.md](../../RESIDENT_SUPPER_PLAN.md) を作成した。

## 遊び方

「三つの岸の湾」→「共同の食料置き場」→「住人の夕食」で、集落と食べ物を選ぶ。炉から9m以内で、もちものから一つずつ夕食を取り分ける。ベリー・焼き肉・焼き魚・焼いた貝・焼き根・香草焼き根の6種類。取り分け済みの食品だけを住人が使い、通常の共同食料を自動で取らない。

共同食料と夕食は合計48個まで。残った夕食は一つずつ共同食料へ戻せる。プレイヤーが戻した食料を受け取る時は、従来の四集落共通・一日3個に従う。受取回数、農地、物々交換、手伝い、宴の仕組みを保つ。

住人は既存の4分の日の夕べ（120〜180秒）に、炉の席へ到着して一人一日一つ食べる。参加者のいる部屋でのみ進み、止まっていた日数分を後でまとめて消費しない。会話中・移動中は待つ。三国の世帯は道中には食べず、集い場への滞在中は集い場で参加する。同じ日に帰郷や移動をしても、もう一度は食べない。

各集落で過ごす人の順番を日ごとに巡回する。食事可能な人が同時にそろった時、毎日同じ人を先にしない。仕事場からの到着時刻や会話によって順番は変わる。食品の選び方も巡回し、国や種族で食事を独占しない。

食べ終えた住人は8秒ほど炉で過ごし、行動ラベルと案内に食べ物を表示する。既存の待機動作を使い、食器や専用の食べる動作は追加しない。会話、次の日課、世帯の出発が優先する。食料が足りなくても仕事・手伝い・旅を続ける。これはプレイヤーが用意する持ち寄りの夕食であり、住人のすべての食生活ではない。

## 殻と貝塚

住人が焼いた貝を食べると、夕食の場所へ貝殻1個を残す。殻は99個まで。プレイヤーは一つずつ受け取り、既存の指定場所へ運んで貝塚に積める。殻の受取は食品の一日3個を消費しない。殻の置き場がいっぱいなら、住人は貝を残して別の食品を選ぶ。貝以外もなければ待つ。

## 同期と保存

食品・数量・距離・遮蔽・作業・容量・殻の所持上限・競合はサーバーで確認する。食事は住人の現在の場所、日課、世帯の滞在先とサーバーの日付から決まり、プレイヤーが日付や食事結果を指定する通信はない。中心の炉のほか、既存の小さな炉への遮蔽も調べる。小さな炉の石自体が中心の炉を遮っている席でも、実際に囲んでいる炉で食べられる。

夕食、残された殻、各人の最後の食事の日・場所・食品を既存の保存へ含める。食事後8秒の待機は復元しない。旧保存の共同食料と進行を保ち、欠けた夕食・殻は0、食事記録は未記録にする。無効な食品・場所・未来の日付は記録に採用しない。状態配信は食事が起きた時にも共有在庫を送り、選択やコントローラーのフォーカスを作り直さない。

## 創作と検証

日課、同意して取り分ける慣習、食品、個数、時間はゲーム上の創作。古代の配給や栄養所要量を復元したものではない。[考古学の背景](../../WORLD_SETTING_PLAN.md)を保持する。腐敗・自動生産・長期栄養収支・人口変化・政治は未実装。通常Nodeのディスク永続化、公開デプロイ、料金変更は追加しない。

新規GLB・可視プリミティブ・テクスチャ・依存パッケージは0。旧モデルを含む既存39モデル・54GLBを照合。テストは [resident-supper.test.mjs](../../tests/resident-supper.test.mjs)、再現は [qa-resident-supper.mjs](../../scripts/qa-resident-supper.mjs)。`GAME_QA_BUILD` で分離ビルドを指定できる。

全体324テストと最終関連21テストで、6食品、容量、二重取得、一日一回、8人の通信競合、保存互換、全住人の夕べの移動、訪問・帰路、各集落内で8日間の順番の巡回を確認した。分離・通常のstrictを含むビルド、構文・依存境界・書式を確認。詳細は `qa-summary.json` と `assets-qa.json`。

実Chrome2画面＋通信3人の最終235観測で、衝突違反・ブラウザーエラー0。6食品の準備、共同食料へ戻す、8人の食事、殻の回収と貝塚、翌日、再読込、390×844／844×390、模擬Gamepadの選択保持・スクロール・戻るを確認。位置・食品・世帯の滞在と午後の仕事場・3回の時計変更は準備値。夕べへの移動と食事は実時間で進めた。初回QAの貝塚ボタンのID指定を既存の `shell-deposit` へ修正して完走。最終の各集落内の巡回調整は関連21テストで再確認した。

通常のローカル反映は `rollout.json` に記録。物理端末・物理コントローラー・大人数負荷・長時間稼働・常時60FPSは未検証。
