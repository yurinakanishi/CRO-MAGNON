# 設定からローカルの部屋をリセット

ユーザー指示「3000番でプレイ中は、settingからリセットボタン」に対応。

## 操作

メニュー → 設定 → 「部屋の進行をリセット」の「リセット」 → 確認画面で「リセットする」。確認時は「やめる」にフォーカスする。Esc・コントローラーの×・「戻る」で設定へ戻り、進行を変えない。成功すると接続中の全員が同じ部屋へ初期状態で再参加する。名前と選択キャラクターは保持する。

## 対象と保存

- 通常Nodeの永続サーバーは3000番で既定有効。ループバックからlocalhost／127.0.0.1／::1宛ての接続に限定。別サーバーへ接続する展示クライアント、他のポートの既定設定、公開版ではボタンを出さない。QAの独立サーバーのみ `enableRoomReset: true` を指定する。
- HTTPは同一OriginのJSON POSTと、対象の部屋に接続中の本人のセッショントークンを確認する。トークンをログや検証要約に出さない。
- `application/game-core.mts` の `resetRoom()` は対象の入力・tick・新規参加を一時停止し、その部屋を取り除いた保存を先に書く。保存失敗では現在の部屋・持ち物・接続を保ち、処理を再開する。成功後のみ部屋と旧再開情報を破棄し、`roomReset` 通知で画面を更新する。
- 自動保存と終了保存はリセットと直列化する。他の部屋の状態は保存に残す。旧ソケットの遅れて届いた入力／切断処理が新しい部屋を消したり旧進行を戻したりしないよう、部屋オブジェクトの一致を確認する。
- リセット自体にサーバーの再起動は不要。モデル変更なし。

## 検証

- `tests/local-room-reset.test.mjs`：有効範囲・Origin・本人確認、共有進行とオフライン再開情報の削除、他の部屋の保持、実保存と再起動、実際の書き込み失敗、重複実行・処理中の入力と参加を検査。
- `scripts/qa-local-room-reset.mjs`：独立した保存先と実Chrome 2画面＋通信3人、別部屋1人。設定・キャンセル、模擬コントローラーの○／×、失敗後の再試行、5人の初期化と再参加、別部屋の保持、画面再読み込みと保存を確認。1440×900、390×844、844×390で撮影。5項目合格・画面エラー0。
- 実Chromeの記録は `output/playwright/local-room-reset/`。保存失敗の単体検査は、全体テストの負荷で参加直後の保存がまとめられる場合を考慮し、予備ファイルが生成される2回目の保存完了を明示的に待つよう修正。
- 通常3000番は有効フラグと配信ファイルを読み取り確認するだけで、今回の確認のためにユーザーの部屋をリセットしない。

物理コントローラー、長時間負荷は未確認。公開デプロイ・展示／PC2更新・コミットは実施しない。
