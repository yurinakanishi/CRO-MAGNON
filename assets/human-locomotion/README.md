# 人間の歩行・走行を実測モーションから修正

2026-09-13。ユーザー指定「人の関節がクネクネ曲がるのをやめて、自然な歩き・走りに。指定記事を参考に、Tripoは一切使わない」に対応。

## 採用した内容

- クロマニョン人・ネアンデルタール人の男女4体と、人型の猫耳キャラクターの `Walk_Loop` / `Run_Loop` を `model-human-r10.glb` に更新。これらのアセットを共有する住人にも適用する。
- 実際の人を計測したCMUの歩行・走行を既存の骨格へ移した。膝の向き、足首、腕の振り、骨盤・胸の体重移動を同じ記録から作る。前の走行のように、手作業で独立に作った足先・腰・腕の曲線を組み合わせない。
- 足の長さ、足裏、肩幅の差を調整。膝と肘には連続する曲げ面を使い、骨の長さを変えない。つま先の向きは記録を70%混ぜ、手指の未計測チャンネルは使わない。マーカー由来の細かな揺れとループ境界を周期フィルターで整える。
- 形状、骨の配置、スキンウェイト、UV、材質、画像、待機、両手槍攻撃、倒れる姿勢など他のクリップは保持。元のGLBバイナリをそのまま先頭に保持し、歩走のキーを末尾へ追加する。旧 `model-run-r05.glb` を含む配信履歴も保持。
- 猫耳の新クリップには姿勢と前傾が含まれるため、以前の `LeanPose` を重ねて二重に前傾させない。
- 待機・歩行・走行を混ぜる短い切替中だけ、実際のスキンの足裏を測ってHipsを持ち上げる。関節角度やサーバーの位置は変えない。次のミキサー更新前に補正を戻す。回転・平行移動・拡縮した親の下でも同じ床として扱う。

## 資料と制作方式

指定の[記事](https://www.tripo3d.ai/blog/gpt-6-astra-3d-character-workflow)は、既存リグの曲げ姿勢を確認し、使える動作を移し、書き出した結果を再生して改善する流れの参考として読んだ。Tripoの生成、API、リギング、アップロードは使用していない。Claudeも使用していない。

動作の出典は **CMU Graphics Lab Motion Capture Database**。モデルの外見は既存のTRELLIS系統のまま。ASF/AMCをローカルで読み、Three.jsで骨格へ移してGLBを書き出し、ChromeとBlender 5.2で再読込した。

| 動作 | 元データ | 使用区間（AMCの1始まり） | 周期 |
| --- | --- | --- | --- |
| 歩行 | [35_01](https://mocap.cs.cmu.edu/subjects/35/35_01.amc)、[骨格35](https://mocap.cs.cmu.edu/subjects/35/35.asf) | 140〜274、周期末尾は先頭へ一致 | 1.116667秒 |
| 走行 | [09_01](https://mocap.cs.cmu.edu/subjects/09/09_01.amc)、[骨格09](https://mocap.cs.cmu.edu/subjects/09/09.asf) | 1〜89、位相を80フレームずらす | 0.733333秒 |

120Hzの記録から120Hzで焼き込み。関節は実測由来だが、足裏に合わせる高さ、走行の短い浮遊（身長の1.8%を上限とする曲線）、腕の胴体からの距離、頭の動きの45%への抑制は、このゲーム用の手作業による調整である。新しいモーションキャプチャ撮影をしたという意味ではない。比較した遅いジョギング35_17も未採用資料として保存した。

[CMUの利用案内](https://mocap.cs.cmu.edu/)と[FAQ](https://mocap.cs.cmu.edu/faqs.php)を2026-09-13に確認。製品内での使用が認められている。データ自体の再販売は行わない。

> The data used in this project was obtained from mocap.cs.cmu.edu. The database was created with funding from NSF EIA-0196217.

原データ・確認したページは `source/`、ファイルのURLとSHAは `sources.json`、変更前のマニフェストは `source-manifests/` に保存。

## 検証

- 最終GLBを240Hzで検査。5体×歩走で膝の反転なし、骨の伸縮誤差は最大約0.0052mm、ループ表面差は最大約0.00035mm。膝屈曲は歩行約14〜75度、走行約3〜115度。走行の膝角速度は元の周期で最大約668度/秒。
- スキン足裏の最低値は約2.55mm。歩行には浮遊がなく、走行は約22〜23%で両足が離れる。骨盤の上下幅は歩行約3.0〜3.9cm、走行約4.1〜7.4cm。
- 歩走を32位相×3混合比で検査。補正前は最大約4.74cmの足裏沈み、補正後は全5体で床上2.52mm以上。関節の回転値は補正前後で完全一致。
- 実時間の待機→歩行、歩行→走行、走行→歩行、走行→待機を、移動・回転・拡縮したモデルで検査。新しい `tests/locomotion-grounding.test.mjs` が退行を検出する。
- Chromeで5体×5方向×6時点×2動作の画像と、修正前後を並べた30fps動画を制作。Blenderの無彩色表示でも女性の膝・肘・脚の輪郭を確認。
- 最終Chrome QAは実画面2＋通信3の5人で実施。全7キャラクターの21歩走区間、画面間同期、ジャンプ・攻撃からの復帰、女性による橋の横断・旋回・停止、390×844／844×390、女性での再読込を確認し、エラー0。変更した5体の実描画中の足裏を344回測定し、中心の床面から最低2.519mm。橋の画像は保存したが、QAホスト側の高さアトラスは未導入だったため `bridge.json` のy=0は実描画の高さ計測として扱わない。
- 通常3000番の新GLB5件とアニメーション関連JS3件は、ディスク上の最終ファイルとSHA一致。サーバーの手動再起動は不要だった。
- 資産検証は42モデルで合格。全583テストのうち、従来から時間切れが発生している保存テスト1件が全体実行で時間切れになり、当該ファイルと新規検査の計14件を再実行して合格した。型（strictを含む）、構文、依存境界の結果は `checks.json` に記録する。

実ゲームの最終結果は `game-qa.json`、配信URLとSHAの照合は `delivery.json`、各モデルのレビューは `reviews/` に保存する。画像・動画・測定の詳細は `output/playwright/human-joints/revision-10/`、Blender画像は `output/blender/human-locomotion/`。

## 制作履歴と残る範囲

revision-06はジョギング35_17の初期移植、07は速い走行09_01と肩幅補正。08〜09で試した骨盤の平滑化＋足先IKは膝の角速度を増やしたため不採用。10は実測由来の関節角度を保ち、全足裏の検査とつま先の調整を採用した。途中GLBは `output/player-gaits/` に別revisionとして保持。

現在のゲーム速度と再生倍率の上限は保持しているため、高速移動時の足滑りは残る。接地補正の床はキャラクター中心の床面であり、左右の足をそれぞれ別の坂・段差へ追従させるIKではない。全メッシュの自己交差、全装備と服の接触、物理コントローラー、長時間負荷は未検証。公開デプロイ、展示・PC2更新、通常3000番サーバーの手動再起動、コミットは行っていない。

## 再現

```text
node scripts/build-human-locomotion.mjs revision-10
node scripts/verify-human-locomotion.mjs revision-10
node scripts/serve-player-gaits.mjs
node scripts/qa-human-locomotion.mjs revision-10
node scripts/video-human-locomotion.mjs revision-10
node scripts/adopt-human-locomotion.mjs revision-10
node scripts/qa-human-locomotion-game.mjs
```

動画にはローカルFFmpeg（`FFMPEG`環境変数で場所を指定可能）を使う。骨格やアニメーションの変更時は別revisionへ保存し、旧版を上書きしない。
