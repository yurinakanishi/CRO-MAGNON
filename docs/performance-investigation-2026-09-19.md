# 2026-09-19 カクつきの原因調査と改善

実Chromeで開始地点・洞窟・城の静止と歩行を調べ、描画CPU、フレーム間隔、各処理の所要時間、描画回数・三角形数、長時間タスク、通信量を記録した。単に解像度やモデルの品質を落とす変更はしていない。

## 再現した原因と修正

1. **川岸の生成が移動を止める。** `OpenWorldTerrain.admit` が川岸の元メッシュを細分化し、頂点を統合して法線を計算していた。フレーム当たり3msという外側の制限では、内部の100ms級の処理を分割できなかった。専用のmodule Workerで同じ計算を実行するようにした。転送するのは複製したバッファだけで、共有GLBは変更しない。最初の近傍の床は準備完了を待ち、以後は完成した区画を取り込む。退出後・素材解放後の結果は破棄し、ワールド終了時はWorkerと待機ジョブを終了する。
2. **新しく画面に入った敵の全頂点をCPUで変形していた。** Three.jsのSkinnedMeshは初めて必要になったときに外接球を求める。城を歩く5秒間で、4体の計算に合計162.6msを要した。骨が受け持つ頂点の範囲を初回に一度だけ求め、同じメッシュを使う個体で共有する。毎フレームは骨の変換行列から保守的な外形だけを求める。表示判定用で、骨格・クリップ・頂点・ゲームの衝突判定を変更しない。移動・回転・非一様スケールも扱い、古いポーズの外形が残らないようにした。
3. **動かない地形や非表示の骨格も更新していた。** 不変のSceneと地形ルートの自動行列更新を止めた。距離で非表示になった人物・敵・動物・肉の描画ルートは、通常の描画時には子をたどらない。再表示時は現在の変換を反映し、明示的な座標問い合わせや強制更新は従来どおり動作する。

光源数・シェーダー数も調べたが、城の上記の停止時にはどちらも変化していなかった。光源を固定枠へ置き換える案は採用していない。通信は今回のローカル観測で約10通/秒・約200KB/秒だった。通信仕様の変更はしておらず、遠隔回線の遅延・帯域制限への改善は主張しない。

## 変更前後の実測

環境はWindows、Chrome headless、ANGLE / AMD Radeon(TM) Graphics / Direct3D11。1描画画面、通常1280×800、pixel ratio 1。場面準備としてサーバー上のプレイヤー位置を設定し、10秒待ってから静止5秒・実際のWキー歩行5秒を記録した。そこまで歩いて到達した検査ではない。各セルは単回の5秒観測で、平均FPSの一律向上や全ての停止の解消を意味しない。

| 通常条件 | 変更前 | 最終版 |
| --- | ---: | ---: |
| 開始地点・歩行の最長フレーム間隔 | 112.4ms | 25.8ms |
| 開始地点・歩行の平均描画CPU | 4.81ms | 2.99ms |
| 城・歩行の最大描画CPU | 43.6ms | 9.5ms |
| 城・歩行の最長フレーム間隔 | 43.9ms | 28.7ms |
| 城・歩行の平均描画CPU | 4.56ms | 3.52ms |
| 洞窟・歩行の平均描画CPU | 2.60ms | 2.18ms |

通常条件のフレーム間隔の中央値は全場面で前後とも約16.7ms。今回の主な効果は移動中の大きな引っかかりと余分なCPU処理の削減。開始地点の静止は139描画・1,879,990三角形、洞窟の静止は36描画・1,333,410三角形で前後一致した。アニメーションする外形は安全側に判定するため、歩行中の画面端では描画対象が少し増える場合がある。

追加で1920×1080・ChromeのCPU処理速度を4分の1に制限した条件を比較した。開始地点を歩く際の最長フレーム間隔は488.8→62.7ms、平均描画CPUは27.22→21.85ms。川岸処理のメインスレッド合計は792.1→68.4ms。p95のフレーム間隔は48.1→49.5msで改善しておらず、この負荷条件で安定60FPSには達していない。これは人工的なCPU負荷で、別の実機性能を再現した数字ではない。

GPU実行時間は直接測っていない。洞窟の静止では最終版でも描画処理外の約82msのフレーム間隔が1回あり、ブラウザーやOSを含めた全停止の解消は確認していない。

## 検証

- 全629テスト合格。TypeScript・新規処理のstrict検査、343JSの構文検査と追加した集計スクリプトの構文・実行、依存境界、書式・差分チェックも通過。
- 実ブラウザーで24個の川岸メッシュを元の同期生成と比較。頂点座標・法線・UV・インデックスが完全一致。
- 11モデルの全配信クリップについて各3姿勢の全頂点を、新しい外形が含むことを検査。移動・回転・非一様拡縮した親、複製個体も検査。
- Workerの初回要求、直列実行、起動・実行失敗、待機中の終了、遅れて到着する地形の破棄を検査。非表示からの復帰と明示的な座標問い合わせも確認。
- 実際の歩行・攻撃、雪原へ移した準備場面と帰還後の再読込、5接続（2描画画面＋通信3人）での移動同期、再読み込み時のID・位置・持ち物保持、390×844／844×390の持ち物と地図を確認。ブラウザーエラー0。
- 通常3000番の変更・追加14モジュールがビルド結果のSHAと一致。再読み込みで反映される。通常サーバーの手動再起動は行っていない。

GLB・モデルマニフェスト・解像度・LOD距離・戦闘仕様は変更していない。公開版・展示パッケージ・PC2は更新していない。実機スマートフォン、5画面同時描画、長時間の負荷、遠隔回線は未検証。
