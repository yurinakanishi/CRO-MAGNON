# 人物選択の身長比・スマホ表示と、クノイチの保管

2026-10-15のユーザー指定により、スマホの人物カードの縦長な余白を減らし、写真をゲーム中の実際の身長比へ変更した。猫耳のクノイチと刀は、選択・読み込み・通常配信・公開用ビルドから除外し、すぐ復元できる状態で保管した。公開サイトへの再デプロイは行っていない。

## 写真とスマホの表示

全員を縦2.24mの同じ平行投影範囲で撮影し、足元を揃えた。配信モデルの高さは大猿約2.00m、人間男性約1.80m、ちび女性約1.45m、砂耳の魔法使い約0.78m。人物ごとに画面いっぱいへ拡大する旧写真を置き換え、選択時の画像拡大もやめた。モデルや材質、動作、ゲーム内の身長は変更していない。

有効な14人物×9色の126枚を撮影・採用。通常のローカル設定と公開用ビルドではまるぃもを除く13人物×9色の117枚になる。元PNGと可逆WebPの可視RGB・透明度の一致、全身と色、元GLB・配信GLB・写真のSHAを確認した。クノイチも同じ条件の9枚を復元用に別revisionで撮影・保管し、現在は配信しない。[撮影記録](../assets/character-portraits/README.md)。

スマホの人物列は画面の残りの高さを埋めず、縦持ちでは208〜260pxに収める。短い画面ではフォーム全体をスクロールし、色と「これにする」へ進める。ゲーム中の変更と横持ちは別の高さ上限を使う。写真の枠は名前の長さによらず同じ寸法で、足元と身長比を揃える。320×568、390×844、430×932、768×1024、844×390で確認した。途中候補の128pxでは短い画面の写真が小さすぎたため不採用とした。

## 除外する範囲と保管

`shared/character-roster.mts` の `species: 'cat'` を `enabled: false` にし、`cat-kunoichi` と `kunoichi-katana` を同じ設定にまとめた。

- 初回・選び直し・ゲーム中の人物変更、公開人物プロフィール、ブラウザーのモデルカタログから除外。
- 参加・変更のリクエストへ直接指定しても、無効な人物にはならない。
- 通常ローカルではGLB・LOD・manifest・旧肖像・色別写真の直接URLを404にする。大文字やURLエンコードを使った経路も対象。
- 公開用ビルドのファイル一覧・カタログ・服の色規則から、本体と刀を除外。終了した展示向けの収集コードも名簿に従うようにしたが、展示用ビルドは作成していない。
- `public/models/cat-kunoichi/` と `public/models/kunoichi-katana/` の元GLB・LOD・リグ・動作・manifest・旧肖像を保持。色別写真の新旧revisionと制作記録も保持する。

以前クノイチだった保存は、有効な人物で再開しつつ元の外見を非公開の `unavailableCharacter` に残す。持ち物・進行・プレイヤーIDは保持する。ユーザーが別の人物を明示的に選んだ場合は、その選択を優先する。

## すぐ戻す手順

ユーザーから復元の依頼があった場合にだけ実施する。

1. `shared/character-roster.mts` の `species: 'cat'` の `enabled` を `true` にする。`nea` の設定は変更しない。
2. `npm run build` と関連する検証を実施する。人物定義・本体・刀・服の色規則・現在の写真revision `choice-r04` の9枚（2026-10-16にB5の追加で全員をr04へ撮り直したとき、クノイチも [復元用](../assets/character-portraits/20261016-r04-cat-restoration/restoration.json) に撮影済み）がすでに揃っているため、モデル制作や再撮影は不要。
3. 通常の配信フィルターと公開用ビルドが本体・刀・写真を一緒に復帰させる。非公開で保持していた外見は、別の人物を選び直していない保存で復帰する。
4. 公開サイトへ戻す場合は、公開を依頼されたときに [Cloudflareの手順](../CLOUDFLARE_DEPLOYMENT.md) でビルド・料金条件・反映を検証する。古い保存の再適用は不要。

## 通常3000番と保存

作業前の保存を `output/character-scale-20261015/save-before/` に控えた。作業後、通常3000番の124ファイル（コード7・写真117）のSHAが一致し、除外した37経路が404、health／status正常・参加者0人だった。

10保存セッションのうち、以前クノイチだった1件だけが通常の保存処理で有効な人物へ正規化され、元の外見が `unavailableCharacter` に入った。この外見の変更を除き、10件すべての保存セッションは作業前と一致した。部屋内の動物・敵の移動に関する一時状態も通常処理で正規化されているため、保存全体のバイト一致とはしていない。検証記録は `output/character-scale-20261015/serving-and-save.json`。

保存の手編集・再適用、既存サーバーの手動停止／再起動、公開サイトへのアップロード、展示用ビルド／配布、commit／pushは行っていない。実スマートフォン・Safari・物理パッド・全体テスト一括実行は未検証。
