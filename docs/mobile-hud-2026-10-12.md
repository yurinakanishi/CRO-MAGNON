# スマホHUDの刷新（2026-10-12）

ユーザー指定「スマホ時のHUDがデザイン、UI, UX悪すぎる。直して。大きく刷新してよい。」に対応し、タッチ端末のプレイ中HUDを作り直した。PCのキーボード／パッド用HUD（入力図・プロンプト）は変更していない。

## 変更前に観測した問題（390×844・844×390・360×640・430×932の実Chrome）

- 上部に状態欄・4つの大きな角丸ボタン・「視点を戻す」の文字ボタンが段になって重なり、縦画面の上1/3を覆っていた。メニューと持ち物のボタンは同じ画面（持ち物タブ）を開く重複だった。
- 行動ボタンが文字入りの幅広い角丸で、Webのフォームに見えた。状況別の行動（撫でる・見る）と能力（呼ぶ・投げる・松明）が左右に散らばり、最大5つ並んだ。主となる行動の区別も弱かった。
- 地名バナーは `left:50%` の絶対配置で使える幅が画面の半分に制限され、「ヨーロッパの草原」が2行に折れて副題と重なった。
- 保護中・ダウン表示、通知、焼いている進み具合が画面中央付近の同じ帯で重なり得た。同じ通知が連続すると3枚積み重なった。
- 移動パッドが左下の固定位置で、指を正確に置く必要があった。歩く／走るは文字で表示していた。
- 会話は閉じている間に届いても気づけなかった。
- メニューのタブが横スクロールで、3つ目のタブが「戻る」の下で切れて見えた。

## 新しい構成

画面中央を世界のために空け、操作は両端へ寄せる。半透明の丸いコントロールに統一し、状況によって意味が変わるものだけに文字を付ける。3D画面の上でのbackdrop blurは使わない（スマホの描画負荷のため）。

- 左上：顔・名前・人数・日・体力を1つのカプセルに統合。部屋コードは部族の画面へ（カプセルを押すと従来どおり開く）。体力の数値はバー内。
- 左の細いレール（44px）：メニュー（持ち物タブから開く）・連れていく仲間・会話・視点を戻す（円形の矢印、かんたん操作では非表示）。重複していた持ち物ボタンを削除。会話は未読の点と、他の旅人の発言を5秒間だけ横に出す吹き出しを追加（自分の発言・システム文・地図ピンは出さない）。
- 左下：移動パッドは触れた所に現れる（左下の領域：縦画面は幅50%×高さ40%、横画面は40%×74%）。休止中は角に薄く表示。深く倒して走ると縁が琥珀色に光る。不感帯・走行の切替幅・半径比（基部の0.32）は従来どおり。
- 右上：丸いミニマップ（縦84px／横76px）と北の印、その下に地名。接続中は緑の点だけで、切断時だけ「再接続中…」等の文字を出す。丸く切り抜く表示ではミニマップ画像内の地名と縮尺を描かない（`data-compact`）。
- 右下の行動パッド：角に大きな攻撃（装備に応じた槍・刀・魔法・科学・素手・触手の記号、再使用までの時計回りの減り表示）、左にジャンプ（二重の上向き山形）、上の弧に能力：投げる／松明は親指に近い位置、みんなを呼ぶはその上。能力には左側に短い名前を付ける。
- 状況別の行動（撫でる・採集など・乗る・船・見る）は最大3つ。行動パッドのすぐ上に下から積み、一番下（親指に最も近い）を琥珀色の主行動にする。能力の有無で高さを詰め、横画面では行動パッドの左に並べる。焼く・船を出す・船を回収・肩乗りの誘いを断るもこの行動として出す（従来のホットバーのボタンはタッチでは非表示。「断る」は以前のスマホ表示では押せなかった）。
- 作業中（焼く・釣り・貝・石器）と仲間を近くで見る間は、攻撃・ジャンプを隠し、「やめる」または「近く／遠く／戻る」だけを親指の位置に出す。作業の進み具合は「やめる」の真上。
- 通知は中央の帯を分ける：地名（21%）・通知（30%、最新2件）・保護中（41%）／ダウン（42%、通知より手前）。同じ通知が続いた時は積み重ねず最新の1枚を出し直す（PCも同じ）。
- メニュー（860px以下のタッチ）：4つのタブを1行に収め、記号の下に名前。戻るは丸い角のボタン、「その他の操作」は全幅。幅520px以下では全画面（セーフエリア内）にして、320px幅でもタブ名を折り返さない。
- 焚き火で生肉を焼く操作が近くの行動として出ている間は、別の「肉を焼く」を重ねて出さない。

## 実装

- `src/touch-input.ts`：`touchLayout`（行動3つまでの優先順、能力の分離、焼く・船の追加）、`touchSkillSlots`、`touchIcon`、`touchWeaponIcon`。既存の `touchActions`・`touchStick`・視点追従は維持。
- `src/touch-controls.ts`：レール・浮く移動パッド・行動・能力・攻撃の再使用表示・会話の未読と吹き出し。DOMの書き込みは `hud-dom.ts` の差分書き込みで、表示が同じなら書かない。
- `src/touch-controls.css`：HUD部分を全面的に書き換え。開始画面・会話シートの規則は保持。
- `src/main.ts`：タッチへ武器・再使用・焼く／船の行動を渡す、`cook`／`launch`／`recover` の実行、会話の吹き出し、丸いミニマップ、通知の重複防止、設定の説明文。
- `src/world-map.ts`：丸いミニマップでは画像内の地名・縮尺を省き、地図ピンを円の縁へ寄せる。
- `src/icons.ts`：ハート・手・目・マンモス・呼ぶ・投げる・松明・マイナス・戻る・触手・視点を戻すの線画を追加し、ジャンプを二重の山形へ変更。
- 英語：新しい読み上げ名と設定の説明文を追加し、使わなくなった3項目を削除。
- QA：`scripts/qa-mobile-chat.mjs` のレールの期待値（menu・mascots・chat・center）と、二本指の検査で親指を一度動かしてから会話を開くように更新。新規 `scripts/qa-mobile-hud.mjs` が新しいHUDの配置・浮く移動パッド・行動と能力・攻撃の再使用・焼く→作業中・会話の未読・通知の重複防止とダウン表示・近くで見る・洞窟の松明・英語・メニュー・4画面寸法を実Chromeで検査する。`scripts/qa-input-cues.mjs` と `scripts/qa-cave-actions.mjs` は、待機中の洞窟（2026-10-07以降の入場）で「進む」を押さずに世界の準備完了を待って必ず時間切れになっていたため、他の検査と同じ `enterPreparedWorld` で入場するように直した。`qa-cave-actions` は画面寸法ごとに松明を消す前にもサーバーの操作間隔（450ms）を待つようにした（新HUDは3回目の切り替えを送っていたが、直前の再点灯から450ms以内のためサーバーが無視していた）。
- `src/style.css` は全HUD要素へ共通の `z-index: 2` を与える（高い詳細度）。タッチ側でダウン表示だけを上げるときはIDセレクターを使う。

## 検証

保存なしの独立サーバー（ポート自動割当）と実Chrome（ヘッドレス、`hasTouch`・`isMobile`、CDPのネイティブ指入力）で確認した。ゲームサーバー側の準備（位置・所持品・ダウン状態の設定）と、指による実操作を区別している。物理のスマホ、iOS Safari、Android Chromeの実機は使っていない。

- 単体：`tests/touch-input.test.mjs` に、行動を3つまでに絞る優先順・作業中／近くで見る間の行動・能力の位置・行動と武器の記号の2件を追加。関連26件に合格。全体1,491件では1,486件合格・4件条件付きスキップ・1件失敗。失敗は `tests/context-recovery.test.mjs:372`（待機中の洞窟の移動入力を離した後の形）で、今回より前のコミット `8cc938f` が `running: false` を加えたことによる既存の不一致。今回の変更では触れていない（別作業として提案済み）。
- `npm run check`（型・strict・621 JS構文・依存境界）、変更したTypeScriptと検査スクリプトのPrettier、差分空白に合格。
- `scripts/qa-touch-portrait.mjs` 10項目に合格（浅い／深い親指、解放とOS取消での停止、二本指の視点操作と移動方向の保持、ジャンプ・攻撃の1回実行、移動中の二本指ジャンプ、撫でる・投げる・呼ぶ、メニューでの停止と設定・仲間・地図、390×844・320×568・430×932・844×390で44px以上・重なりなし・指が当たる、会話中の停止・PC表示・別画面への同期・再読み込み、余分な送信と例外なし）。証拠 `output/playwright/mobile-hud-20261012/touch-portrait/`。
- `scripts/qa-mobile-chat.mjs` 5項目に合格（新しいレール、二本指で会話を開くと移動停止、日本語と絵文字の送受信、下端のシートの寸法、模擬キーボード、PCのEnter）。証拠 `.../mobile-chat/`。
- 新規 `scripts/qa-mobile-hud.mjs` に合格し、ブラウザー例外0。最終は洞窟の松明を加えた12項目（`.../hud-qa-r2/`）。初回はダウン表示の重なり順の検査で失敗し、`style.css` の共通HUD層を確認してIDセレクターで修正、再実行した（`.../hud-qa/` は修正後の11項目）。
- 洞窟：入場と操作間隔の待ちを直した `scripts/qa-cave-actions.mjs` は、タッチの縦3寸法と横画面で松明だけを持ち攻撃・拾う操作が無効なこと、5接続の明かりの同期、焚き火の点灯を含む5項目に合格。その後のPCだけの「洞窟を出ると石斧が戻る」で失敗した。原因は検査が旧来の `p.tool = true` で石斧を装備させていることで、2026-10-11の装備変更後は `equippedItem` が必要（今回のHUDとは無関係。別作業として提案済み）。証拠 `.../cave-actions-r3/`。
- PCとパッドへの影響の確認として、入場を直した `scripts/qa-input-cues.mjs` 7項目（キーボード、Switch／PS／Xbox／汎用パッドの抜き差しと全ボタン、撫でる・投げる・呼ぶ、マウス、メニュー・地図、2描画＋3通信、縦横とPCの寸法）に合格し、ブラウザー例外0。証拠 `output/playwright/input-cues/1791762303379/`。
- 撮影用の補助スクリプトで、待機・撫でる・能力・低体力・走行中の浮く移動パッド・会話の吹き出し・焼く→作業中・近くで見る・切断表示（表示のみの模擬）・英語・ダウン・メニュー・横画面・小／大画面を目視確認した（`.../states/`、スクリプトは同じ場所の `capture-states.mjs`）。変更前の画面も同じ手順で保存した（`.../before/`）。

未検証：実スマホでの指の届き方と押しやすさ、iOS Safari／Android Chrome固有の表示（セーフエリア、アドレスバーの伸縮、`text-wrap`・`translate` プロパティの対応）、端末回転の実機挙動、持続fpsと発熱。HUDからblurを外したことによる描画負荷の差は測定していない。
