# アプデの洞窟を覆う丘（2026-10-05）

ユーザーの追加指定により、入口を地上のまま維持し、洞窟の上と側面を高さ約18mの草と土の丘へつないだ。洞窟・キャンプ・城の配置、壁画、仲間、保存形式は変更しない。

## 実装

- 元の山裾は洞窟の中央付近で終わっていたため、既存TRELLIS山モデルの東側を広げた。近景・遠景の両LODへ同じ座標変換・高さ補正を適用し、測定済みの地面判定には逆変換を使う。元GLBとUVは保持し、別の山形プリミティブは追加しない。
- 洞窟の曲がりに沿う約18mの丘を既存の山へ接続。斜面の立ち上がりを実入口に合わせ、測定済みの屋根に従って開口部だけ切り抜き、側面の土を残す。川側の元岩の張り出しも外向きの面だけ土と草の色に合わせ、内側の石灰岩と壁画を保持。
- 山裾の拡張が川へ張り出さないよう既存の河岸に合わせ、描画と地面判定で同じ河床処理を共有。河岸の急な曲率には元三角形の局所細分化を増やし、UVを補間する。
- 洞窟の測定範囲で草原を隠す処理を保持。床セルだけに絞る案では壁際に草地が見えたため採用しなかった。

## 確認

- 主な屋根の測定4,542点で2m以上の被覆。実GLBの近景・遠景を描画と同じ方法で変形し、18地点ずつをレイ計測。地面判定との差は最大0.026m / 0.043m。7地点ずつで川を塞がないことも確認。
- 関連48テスト成功。全9人物のキャンプ→洞窟→城→キャンプの歩行、登山路の勾配0.35未満、自動経路、内部の床・壁画・火・松明を含む。全体一括検査は未実施。最終の入口形状調整後に対象11テストを再確認。
- TypeScriptビルド、依存境界、484JS構文、対象書式、差分空白が成功。
- 保存なしの独立実Chromeで、前・左右・上からの丘、地上の入口、内部の壁画を確認。実Wキーでキャンプから入洞。1440×900 / 390×844 / 844×390、2ブラウザー＋通信3人、再接続、ページ／consoleエラー0。
- 通常3000番の関連コード7ファイルと元GLB3ファイルがローカルとSHA一致。既存devの自動反映を使用。

初期検査では旧「川から6m以内は常に平地」「城より手前は全て無変形」の期待値が変更範囲と衝突したため、川の流路と変更範囲外を検査する形へ更新。河岸の描画と判定の0.422m差は実装の細分化を修正して解消した。調整前の画像と検査結果概要を保存。
