# スマホ縦持ちのタッチ操作（2026-10-06）

ユーザー指定で、縦持ちのまま半透明の仮想移動パッドと直接押せる行動ボタンを使う方式へ変更。視点は追加確認で「自動追従＋なぞって調整」を採用した。

## 調査した実例と採用判断

- [Sky公式の操作説明](https://thatgamecompany.helpshift.com/hc/en/13-sky-beta/faq/375-how-do-i-get-my-character-to-move/)：左側の移動と右側の視点操作を分け、表示ボタンから行動する方式。本ゲームでも左右の親指の役割を分ける。
- [Microsoftのタッチ操作設計と実例](https://learn.microsoft.com/en-us/gaming/gdk/docs/features/common/game-streaming/building-touch-layouts/game-streaming-tak-designers-guide)：Minecraft Dungeonsの状況に応じた行動の追加、Yakuza: Like a Dragonの深いスティック入力による走行、地図・メニュー・持ち物の直接操作。キー割当を見せる代わりに行動名で触れられるボタンを使う。
- [スクウェア・エニックスのスマホ版ドラクエVIII紹介](https://www.jp.square-enix.com/tgs14/dq8/)：3Dの世界をタッチに合わせて操作しやすくする実例。本ゲームでは操作数を減らし、移動中の視点を自動で追従させる。
- [Appleのタッチ入力設計](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/HTML-canvas-guide/AddingMouseandTouchControlstoCanvas/AddingMouseandTouchControlstoCanvas.html)：指で動かすノブは44×44px以上を目安にする。今回のゲーム用タッチボタンも44px以上、主要ボタンは48～62px、移動パッドは122～136pxを確保。

Webの一次資料を確認した。YouTube映像を視聴したとの主張はしない。各事例から本ゲームに合う操作を選んだ設計判断であり、他作品と同じゲーム挙動の再現ではない。

## 実装

- タッチ端末を認識し、専用HUDを表示。物理パッドを使った場合は従来の入力図へ戻り、タッチへ戻すとスマホ表示へ復帰する。
- 左下の移動パッドに不感帯と走行の切替幅を設ける。斜め移動を正規化。解放、OSキャンセル、画面離脱、回転、メニュー、通信切断で入力を破棄する。
- 1回のパッド操作中は開始時のカメラ方向を基準として固定。視点が追従しても、押し続けた移動が勝手に曲がらない。
- 右下にジャンプと攻撃を保持し、近くの対象に応じて撫でる・採集・乗降・見るを表示。投げる・呼ぶ・松明も直接押せる。PCの3行動の表示制限をタッチへ適用しない。
- 行動は既存の共通ハンドラーへ接続。実行可否と仲間の所属はサーバーで確定する。二本指操作でもタップが省略されないよう接触時に実行し、ブラウザーの遅い互換クリックは重複／次の画面への誤入力として遮断する。
- 移動中だけ滑らかに視点を追従。スワイプ中と終了後2.2秒は手動調整を優先し、停止中は見た向きを保持。視点を戻すボタンと設定の近く／遠くも用意。かんたん・視点自動の選択では従来の完全自動を保持。
- 縦画面の画角を広げ、既存の地形・洞窟・城のカメラ衝突と、遮蔽物から離れたときの滑らかな距離復帰を使用。PCと横画面の画角57度は保持。
- メニュー・持ち物・手帳・仲間を上のボタンへまとめ、地図はミニマップを直接タップ。キー名、入力図、未接続パッド表示、休止中の手操作開始欄をスマホでは非表示にする。
- 会話欄、状態表示、メニューのタッチ領域と画面端の余白を調整。状態・通知は視点スワイプを遮らない。ダウン中もタッチのメニューは開ける。

## 検証

保存なしの独立サーバーと実Chromeを使用。ゲームサーバーの位置準備と、CDPによるネイティブの指入力を区別する。物理のスマホや指、Safariの実機は使用していない。

- 関連48テスト（新規5件）、TypeScript／strict、JavaScript構文、依存境界、対象書式、差分空白を確認。
- スマホの実ゲーム確認：歩行・走行、指を離す／OSキャンセルで停止、二本指の移動とスワイプ、移動中のジャンプ、長押し後の重複発火防止、攻撃、猫の撫で開始・所属・投擲・呼び戻し。
- メニューによる即停止、タッチ設定、全13体の仲間、地図、手帳、会話中の操作停止、再読み込み・再参加を確認。別のPC画面にもスマホの移動が同期した。
- 390×844、320×568、430×932の縦画面と844×390の横画面で、44px以上のタッチ領域、重なり、指が当たる要素、横はみ出しを確認。最終結果の例外は0、攻撃・ジャンプの余分な送信は0。
- PCの既存入力図QAは別の実Chromeでキーボード・Switch／PS／Xbox／汎用パッド、採集・攻撃・投擲・帰還、2描画＋通信3人の5人接続を通過。証拠 `output/playwright/input-cues/1791215500706`。
- 通常3000番の新規2JS、主処理・描画JS、タッチCSSの計5ファイルをローカル配信とSHAで照合。HTMLの新CSS参照とviewport-fitも確認。記録 `output/playwright/touch-portrait-20261006/delivery.json`。

最終タッチ証拠は `output/playwright/touch-portrait-20261006/final`。最終結果は同ディレクトリの `result.json` を正本とする。途中の検査失敗、画像、修正前の記録は時刻付きディレクトリへ保持した。状態表示によるスワイプ遮断、小さい画面の旧会話CSSとの競合、次の画面への互換クリックを修正した。1秒周期のカメラ診断を短く待ち過ぎた検査も修正して再実行した。

実スマホでの指の届きやすさ、iOS／Android固有のブラウザーUI、端末回転時の実セーフエリア、持続FPS・発熱は未確認。全体テストの一括再実行はしていない。3D素材、世界、所属・保存形式、非表示設定を変更せず、ユーザーの保存を手編集していない。既存devを継続し、手動サーバー再起動・公開／展示配布・commit／pushなし。
