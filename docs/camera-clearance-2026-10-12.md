# カメラが洞窟・木・人物に埋まる問題の修正（2026-10-12）

ユーザーの指摘「洞窟や木に人物が近づいたとき、カメラがその中、もしくはキャラクターの中に埋まってしまう問題がありそう」に対し、原因の調査と解決案を示し、ユーザーの「その順で進めて」で実装した。可視モデル・GLBの追加や変更はない（カメラ・当たり判定・描画の実行時制御だけ）。

## 変更前の仕組みと原因

カメラは注視点（人物の頭の高さ）から後ろへ光線を1本飛ばし、当たった手前に置いていた。対象は岩・テント・木の幹などの箱（`CollisionWorld.cameraDistance`）と、城・洞窟の実三角形（`MeshRayGrid`）。木の葉は、視線をさえぎる木を描画から省いていた。

1. **木の葉の判定が前の松の形のまま**：葉を「高さ65%を中心、半径0.34h+0.5の球」とみなしていた（2026-09-14、球状の樹冠の松に合わせた値）。2026-10-07のトウヒは高さ約2.0mから半径約2.0mの裾が始まる（配信GLBの実測。下記）。高さ10mの木で球の下端は2.6m、通常のカメラの高さは約2.4mのため、カメラが裾の中に入っても木が消えなかった。葉の判定は0.18秒ごとの再配置でだけ行われ、入ってから数フレーム遅れた。
2. **最小距離が当たり判定に勝つ**：洞窟・城は `max(0.35, 壁まで-0.2)`、箱は `max(0.6, 箱まで-0.15)`。壁や岩に背を付けると、カメラは壁の中へ置かれた。
3. **光線に太さがない**：ニアプレーン（0.15m）の角はカメラから約0.21m（1280×800）。斜めの壁や入口の縁をかすめると、光線は当たらないまま画面の端が岩を切った。
4. **地面の高さ補正が判定の後**：補正でカメラを上げた後に判定し直さなかった。
5. **山がカメラの判定に入っていない**：洞窟の入口まわりの山（`camp-mountain`、詳細25万三角形）は、カメラが通り抜けていた。山のシェーダーは洞窟の岩の範囲の斜面を描かない（`discard`）ので、山を入れるにはその範囲を除く必要がある。
6. **カメラが近いときの人物の処理がない**：2のとき、カメラは自分の人物の首の後ろ・頭・毛皮の中に入った。他の人物・動物の中にも入れた。
7. **ベリーの茂み**：体が通り抜ける茂み（資源・装飾とも当たり判定なし）にも、カメラが入った（変更後のQAで発見）。

トウヒの半径（`crownProfile`、0.5m帯ごとの最大、単位m、配信GLB `model-c2.opt-b08a6550011bcd90.glb`）：0〜0.5m 0.75（根元）、0.5〜2.0m 0.21〜0.26（幹）、2.0〜2.5m 1.87、2.5〜3.5m 1.98、4.0〜4.5m 1.90、5.0m 1.70、6.0m 1.48、7.0m 1.12、8.0m 0.82、9.0m 0.41、頂点9.99m。

## 変更

| 対象 | 内容 |
| --- | --- |
| 太さのある判定 | `MeshRayGrid.sweep()`（`src/mesh-ray-grid.ts`）：光線の代わりに、ニアプレーンの角までの距離＋0.05mの球（`nearPlaneReach`、1280×800で0.265m、390×844タッチで0.258m）を掃引する。三角形ごとの正確な掃引（面・辺・頂点、両面）で、近いセルから順に調べ、最初の接触より先は調べない。各三角形の外接球を格子を作るときに持ち、掃引の道筋から遠い三角形を数回の乗算で除く。注視点がすでに半径より壁に近いときは、その時点の最短距離（`clearance()`）を半径にする（近づかないが、すぐには止まらない）。従来の `distance()` は位置合わせのマーカー表示が使うため残す。 |
| 箱 | `CollisionWorld.cameraDistance(…, radius)`：箱を半径だけ広げて掃引し、最小距離（0.6m）を撤廃。注視点が広げた箱の内側に入る近さでは、軸ごとの離れの最大まで広げ方を縮める（岩の角に立ったとき全方向で0になった不具合を、変更後のQAで発見して修正）。木の幹（`cameraPassable`）は通り抜け、木は描画から省く。 |
| 判定の順序 | `WorldRenderer.cameraReach()`：まず軌道上の位置を地面・洞窟の床・水面より上へ上げ、注視点からその位置までを箱・城・洞窟・山で掃引する。止まった位置が地面の凹凸の下になったときだけ従来どおり上げる。 |
| 頭上へ逃がす | 掃引距離が1.6m未満で、ピッチを最大0.7rad（上限1.05）上げた方が0.3m以上離れられるときは、カメラを頭上へ上げて見下ろす（上げは6/s、戻しは2.5/sで補間）。上げると離れられるかの判定は0.12秒ごと。 |
| 山 | `MountainCamera`（`src/mountain-camera.ts`）：描画中の詳細度の64m区画ごとに、カメラが初めて届いたときに三角形格子を作る（1フレームに1区画まで）。シェーダーが洞窟の範囲で捨てる斜面は、3頂点とも捨てられる三角形を除く。判定は `mountainCaveClipped()`（`src/mountain-materials.ts`）で、GLSLと同じ定数を共有する。 |
| 木 | 樹冠の形を、配信GLBの頂点から実行時に測る（`crownProfile`、`src/tree-sight.ts`）。カメラから注視点への視線が、形＋0.35mに入る木を描画から省く（`segmentNearTree`）。視線にかかる木は毎フレーム調べ、変わったら0.18秒の再配置を待たずに更新する（`LandscapeInstances.viewHidden`）。 |
| 茂み | 体が通り抜ける植物（`PASSABLE_PLANTS`：`berry-bush`）は、資源・装飾とも木と同じ判定で、その視線から省く。 |
| 自分の人物 | `ActorFade`（`src/camera-fade.ts`）：カメラから体（骨ごとの箱 `skinnedDistance`、持ち物は外接球）までが、球の半径＋0.55mより近いと点描（`alphaHash`）で薄くし、半径以内では描かない。材質は同じ外見の人物と共有なので、自分専用の複製を使う。複製は人物が現れて2秒後（または読み込みが落ち着いたとき）から裏でコンパイルし（`compileAsync`）、リンクが済んだものから不透明度1でも常に身に付ける。これで光源が変わったときは他の材質と同じときにコンパイルされ、薄くするフレームではシェーダーを作らない（最初の実装は、薄くするときだけ複製に替えていたため、最初に薄くなったフレームで220msの停止を観測した）。リンク前は、薄くせず描く／描かないの切り替えにする。 |
| 他の人物・動物 | カメラが体の箱の内側（半径以内）に入った人物・マンモス・敵・NPCは、その間だけ描かない。 |
| 読み込み中の洞窟 | 同じ掃引にした（人物を薄くする処理は入れていない）。 |

## 検証の方法

`scripts/qa-camera-clearance.mjs`（新規）。保存先を出力フォルダーに置いたメモリー内のLOCAL_VERIFY部屋で、ユーザーのサーバー（3000・8787・4173）には触れない。実Chrome（ヘッドレス、`--use-angle=d3d11`）でタイトル→人物選択→読み込みの洞窟→世界の通常の開始手順を通り、ページの入口モジュール（`/src/boot.js`）を転送中に拡張して描画器を観察する（HTML自体を差し替えると、ChromeのLocal Network Accessの確認で通信が拒否されるため）。

- **場所（準備値）**：サーバーの当たり判定で、木の幹に背を付けた位置と裾の内側（キャンプに近い2本）、高さ2.1m・2.9mの岩に背を付けた位置、洞窟の奥・中ほど・入口の内側の左右の壁際、入口の外の崖際の左右。人物の位置とカメラの向き（ヨー12方向×ピッチ−0.3・0.19・0.7、距離5.5m）は準備で与え、その後のカメラの位置・木の表示・人物の薄さはゲームのフレームが決めたものを読む。
- **測る値**（描画されたフレームのカメラで）：clipped＝カメラから最も近い描画中の三角形（洞窟・城の格子、木と岩のインスタンス、山・遺跡・小物・資源、山はシェーダーが捨てる斜面を除く）までがニアプレーンの角の距離より近い。blocked＝注視点からカメラまでの線分が描画中の三角形を横切る。selfClipped＝自分の人物（スキン済みの全頂点）のうち不透明度0.5以上で描かれる部分が、ニアプレーンの角の距離より近い。insideActors＝他の人物・動物の箱の中。
- **回転**：木2か所・洞窟2か所・岩で、90°/秒で約1.05回転し、描かれた毎フレームを同じ値で調べる（静止した向きでは見えない、葉の判定の遅れなどを捉える）。
- **負荷**：同じ回転を測定なしで8秒行い、描画器のシミュレーション時間（0.8/0.2の移動平均を毎フレーム展開）の中央値とp95。CPUの比較で、GPU時間・FPSではない。
- **変更前**：`HEAD`（`17d31ec`）の `src`・`shared` 等を `git archive` で取り出してビルドし、`--browser` で同じ素材・同じサーバー・同じ手順に差し込んで同じQAを実行した。

## 結果：負荷（このPCのCPU。実スマホは未計測）

- **交互の変更前後**（`--cost-only`、4か所で90°/秒の回転8秒、描画器のシミュレーション時間）：変更前・変更後を交互に9組。各組の中央値の中央値は、洞窟の奥の壁際 1.6→2.2ms、入口の内側 1.9→1.7ms、木 1.4→1.7ms、岩 1.3→1.4ms。同じビルドの組の間で中央値が±0.5〜0.8ms揺れる。最後の3組（最終の実装）の最大フレームは、洞窟の奥で変更後 18／19／11ms、変更前 20／16／9ms。
- **CPUプロファイル**（洞窟の奥、同じ回転）：カメラの判定 `cameraReach` は1フレーム0.275ms（掃引0.213msを含む）。変更前の光線 `distance()` は同じ場所で0.30〜0.34ms。
- **部分ごとの切り替え**（`--ablate`、同じページで洞窟の奥の回転6秒を、人物の点描・茂みの判定・頭上へ逃がす判定・山の掃引をそれぞれ止めて交互に3巡）：止めない場合が0.9〜2.3msと揺れ、どれを止めても雑音を超える一貫した減りはなかった。
- **単体の計測**（`scripts/benchmark-camera-sweep.mjs`、Node、7回の中央値）：洞窟の掃引は1回20µs（変更前の光線は70µs）、山の区画の掃引3.8µs、箱1.5µs。山の区画の格子作りは1区画3.2ms（初回だけ、1フレームに1区画まで）。
- **点描の準備**：裏でのコンパイルを始めるフレームの同期部分は3.7ms（1280×800）、2.9ms（390×844）、1回。最初の実装（薄くするときだけ複製に替える）では、最初に薄くなったフレームが220msになった回があり、現在の方式に替えた。
- 既存の課題として、変更前後とも、three.jsが毎フレーム描画プログラムの選び直し（`getProgram`・`getParameters`、合計約0.9〜1.1ms）をしていることがプロファイルで分かった。カメラの変更とは別の原因で、別作業として提案した。

## 残る制約・未検証

- **頭そのものが岩に近い隙間**：洞窟の入口の右外（`cave12R`、崖と洞窟の外側の岩の間）では、立てる位置で頭が山の斜面から約0.18m、洞窟の外壁から約0.27mにある。どの向きでもカメラは頭の位置に留まり、人物は描かれず、画面の角がわずかに岩に掛かる（QAのclippedの残りはすべてこの地点）。歩ける範囲と岩の見た目の差で、カメラ側では解消できない。
- **背を付けた高い岩の方へ向けたとき**：高さ2.1mの岩に背を付け、カメラを岩の方へ向けると、頭上へ上げても岩の面に当たるため、カメラは頭の位置まで寄り人物を描かない（一人称に近い視点）。
- **地面と他の地形**：開けた地面（32m区画）は従来どおり地面の高さで上げるだけで、掃引の対象ではない。城以外の遺跡・地形の特徴・テント等は広げた箱で、形どおりではない。箱の寸法（`shared/model-bounds.mts`）は作り直し前の `model.glb` から測ったもので、配信中のモデルとSHAが一致しない（8種類。別作業として提案済み）。
- **山の区画の初回**：山の区画に初めてカメラが届いたとき、その区画の格子を作る（このPCのNodeで約3.2ms、1フレームに1区画まで）。その間の数フレームは、その区画を地面の高さだけで扱う。
- **人物を薄くする処理の準備**：点描の複製は、人物が現れて2秒後から裏でコンパイルする（同期部分はこのPCで約5〜7ms、1回）。リンクが済むまでは、近いときに薄くせず描く／描かないの切り替えにする。並列コンパイル（KHR_parallel_shader_compile）のない端末での動きと実スマホは未検証。
- **実スマホ**：スマホの画面寸法（390×844・タッチ）はヘッドレスChromeでの再現で、実機の見え方・負荷は未検証。
- **読み込み中の洞窟**：掃引だけで、人物を薄くする処理はない。
