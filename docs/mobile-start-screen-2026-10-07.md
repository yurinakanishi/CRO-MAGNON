# スマホの開始画面を縦持ちへ合わせる

タイトル・キャラクター選択・難易度・最終確認をスマホの表示領域内へ収め、ページ全体の縦スクロールを止めた。キャラクター一覧は1行の横スワイプへ変更。人数が増えてもカード部分だけ横に動き、戻るボタンは常に画面内にある。

タイトルの絵と開始／画質ボタンへ残りの高さを割り当て、制作・監修・友情出演は横へ流れるクレジット欄にした。既存の全員の名前・アイコン・QR画像を保持。通常の全クレジットと公開版の3名の両方を確認した。

スマホでは開始時に名前欄へ自動で焦点を移さず、キーボードを開かずにキャラクターを選べる。名前・部屋コードは16pxと44px以上の入力欄。visualViewportの高さと位置へ合わせ、狭い入力中だけカードを隠して入力欄と戻るボタンの場所を確保する。Enterで入力を終えるとカードへ戻る。PCの既存の自動焦点・矢印キー・Enterを保持する。

展示の開始場所一覧も、開始ダイアログ内だけ横スワイプへ合わせた。ゲーム中のワープ画面は従来の配置を保持する。

## 検証

- 保存なしの独立した実Chromeで320×568・390×844・430×932・844×390を確認。開始／戻る、一覧のネイティブ指スワイプ、縦スワイプの停止、最後のカード選択、難易度3種と最終確認のボタン、回転、入力の焦点を確認した。全操作対象が表示領域内、44px以上。横スワイプによる誤選択なし。
- visualViewportを360pxへ縮め、入力欄と戻るボタンを確認。これはOSキーボードの模擬信号。実スマホ・Safari・実際のキーボード／セーフエリアは未確認。
- 独立した展示用フォームへ実setup-flowを結び、開始場所の横スワイプと縦横の収まりを確認。既存の展示PC・固定配布物は操作しない。
- PCの名前欄への焦点、Enter→カード、矢印→選択、Enter→難易度→確認を確認。
- ローカルMMOのHTML／JS／CSSを独立した保存なしNode世界へ配信して同じ検査を行い、縦390×844の実タップでゲーム開始と4操作アイコンの表示も確認。ページ／コンソール例外0。証拠`output/playwright/mobile-start-20261007/mmo-final-r06/`、`result.json`と`join-result.json`。

準備中の失敗も`r01`・`r02`・`final-r03`・`extras-r04`へ保持。最初の測定は入場アニメーションの途中だったため、静止後の測定へ修正。画像確認で入力欄の既存CSSが優先されていることを見つけ、16pxと入力の高さを正しい優先度で指定した。展示の検査は既に結ばれた通常フォームとの二重登録で難易度が開いたため、独立したフォームへ修正。製品の展示の選択処理は変更しない。
