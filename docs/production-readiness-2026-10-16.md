## 修正

- タイトルへ戻る時、最後の保存に失敗してもゲームを閉じる問題を修正。IndexedDBのトランザクションが完了してから終了する。失敗時はゲーム・メニュー・保存への排他ロックを保ち、メニュー内に説明を表示して再試行できる。Workerが落ちた場合も保存成功として扱わない。日本語・英語に対応。
- 分離した実ChromeのWorkerで容量不足相当の書き込み失敗を注入し、修正前にタイトルへ戻ってしまうことを再現。ユーザーの保存は使用していない。修正前の画面とログは `output/playwright/production-20261016/exit-baseline/` と `output/production-20261016/exit-baseline.log`。
- 開発・公開ツールの依存監査のHigh 4件を解消。Wrangler 4.129.0→4.151.0、Miniflare 5.20260903.0-alpha→5.20261012.0-beta、sharp 0.35.2→0.35.5、Workers型定義を互換版へ更新。直接依存していたMiniflareのメジャー系列は維持し、Wranglerと同じ版にそろえた。npm/pnpmのロックを同期。新しい画像処理ライブラリーの版も配信キャッシュの識別に含まれる既存設計を保持。
- Playwright 1.64.1を開発依存へ固定し、本番検証に使うQAの個人PC内の絶対パス依存を解消。
- 洞窟の地形テストを、Git管理外の制作途中のreportではなく、同じ数値・SHAを含むGit管理済みの採用記録 `assets/camp-cave/qa/adoption-r28-deep.json` のgeometryへ接続。検査をスキップせず、採用GLB全頂点との照合を保った。

## 再現手順

Node.js 22以上、Google Chrome、依存監査用のインターネット接続を使う。

```powershell
npm ci
npm run verify:production
```

このコマンドは型・strict・構文・依存境界、書式、npm audit、公開用ビルド、全テスト、Workerのdry-run、Cloudflareローカル配信と実Chromeを順に検証する。失敗時はその段階で止まり、成功と記録しない。ビルドは新しい `output/production-<timestamp>/` に保存し、既存ディレクトリーや通常の配信物を置き換えない。`--output-root=output/<新規フォルダー>` も指定できる。

配信台帳に載る全ファイルのSHAとサイズ、余計なファイルの混入、除外人物、ソロ設定、ゲームAPI／DOへの接続境界、HTTPキャッシュ／セキュリティヘッダーを確認する。ゲームの通常操作では配信JavaScriptを差し替えず、DOM上の既存診断値を読み取る。保存失敗試験だけは、使い捨てのブラウザー内のWorkerに障害を注入する。
