# カメラ操作の起動と配信

1. 既存手順でnpm ci。npm run prepare:vendorで固定版JS/WASMの配置とモデルSHAを確認する。
2. npm startまたはnpm run dev。既に動作しているサーバーや保存を初期化しない。
3. ゲーム参加後、左上の「カメラで遊ぶ」を押す。初回はブラウザーでカメラを許可する。
4. 両手のひらをカメラへ向け、指を伸ばして、楽な位置で約1.4秒止める。手首から指先まで映す。顔・肩・肘・全身は不要。
5. 左手をその位置からカメラへ押すと、手が大きく映って前進する。元へ引くと停止。上下だけでは前進しない。左右で旋回、下げると休止。
6. 右手をカメラへ押し、手全体が大きく映ると攻撃。上げるとジャンプ。中央から横へ動かし、中央を通って反対側まで振ると、近くを調べる/拾う/撫でる。アクションの後は元へ戻す。右手を下げる休止操作はない。
7. 手を見失っても、楽な位置へ両手を戻して止めれば自動復帰する。元の位置に近ければ250ms、位置が変わっていたら約1秒で自動調整する。
   移動手が上/左右の画面端へ出た場合、もう片方の手の認識が続く間は直前の移動を600ms維持し300msで減速。
   両手の喪失・古い結果・下への休止では停止する。未確認のアクションは継続/連発しない。
8. メニュー、別画面、通信断等では即停止し、ゲームへ戻ると両手の中央確認を経て自動復帰する。再開ボタンは不要。座り直したら設定内の「手の位置を合わせ直す」。
9. 「通常操作に戻す」でカメラを解放する。タイトル復帰・ページ離脱でも終了する。

「カメラ・操作の設定」で左右の役割を入れ替えられる。カメラを終了して変更してから開始する。
使用するカメラは実機/仮想カメラから選択でき、切り替えると以前の機器を解放して再調整する。
機器名・解像度・受信状態も表示。受信中でも黒い場合はレンズカバーや選択機器を確認する。

## 表示の読み方

映像には両手の各21点と指の骨格を表示する。「手のガイド」で切替、「拡大」で大きくできる。
緑の点は現在の推定位置であり、点ごとの認識信頼度ではない。古い結果の骨格は消す。
「認識の詳細」には左右それぞれ画面内の点数、映像・モデル・入力状態、認識時間・頻度を表示する。

移動欄の「手の大きさ100%」が楽に構えた基準位置。手のひらと指先までの拡大率も別々に表示する。
手全体が14%以上大きくなってから前進し、7%以下へ戻ると止まる。初期調整値であり利用者ごとの最適値ではない。
指を伸ばすだけで誤発火しないよう、手のひらの幅/長さも一緒に見る。
形を確認できない間は前進を止め、指を伸ばす・手のひらを正面へ向ける案内を出す。
画像内の拡大率なので実距離ではなく、身体全体をカメラへ寄せた場合も反応しうる。
攻撃する手にも同じ拡大率のゲージがある。左右へ一度動かしただけでは調べず、反対側まで振ったときに1回発動する。

攻撃入力が届いた場合と、空中・乗り物・クールダウンで実行できない場合はメッセージを分ける。
パネルを小さくする/スクロールするだけではカメラを切らない。
設定にはCPU/GPU・認識上限10/15/20Hz・映像のみ、処理時間と結果間隔の数値を置く。
初期値はHand Landmarker＋CPU Worker・15Hz。展示前の確認は [検証票](testing.md)。

## 配布物

現在のモデルはpublic/motion/hand_landmarker-float16-v1.task、7,819,105 bytes。
SHA256: fbc2a30080c3c557093b5ddfc334698132eb341044ccee322ccf8bcf3607cde1。
出典は [Google配布のfloat16 v1](https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task)。
[モデルカード](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20Hand%20Tracking%20(Lite_Full)%20with%20Fairness%20Oct%202021.pdf)のApache-2.0と同梱MEDIAPIPE-LICENSE.txtを参照。
JS依存は@mediapipe/tasks-vision 1.0.1、lockfileのintegrityを保持。
配信JS/WASM/モデルのサイズ・SHAはpublic/motion/assets.json。
モデルは同梱し、ゲーム起動中に外部から取得しない。旧Poseモデルは履歴として残るが現在のWorkerは読まない。

Nodeのstatic-filesにwasm/task MIME、展示/公開ビルドの収集対象に同じ資材を追加済み。
展示CSPにはwasm-unsafe-evalだけを追加。JavaScriptのunsafe-eval、COOP/COEP、外部認識APIは追加しない。
既存motion-r01 ZIPには今回の手専用モデルへの変更は含まれない。

## ブラウザーと展示LAN

カメラはsecure contextが必要。各PCのlocalhost/127.0.0.1から開き、ゲーム通信だけをLANホストへ接続する。
他PCのhttp://10.10.10.xを直接開くと使用できない場合がある。セキュリティ設定を無効化して回避しない。
HTTPSのiframe埋め込みではカメラ許可も必要。
WASM SIMD、module Worker、OffscreenCanvas対応のChrome/Edgeを想定。
起動失敗は理由を表示して解放する。GPU失敗時は終了してCPUを選択。Safari/スマートフォン実機は未検証。

## 集計

開発用のresetMotionMetrics()/motionDiagnostics()は状態・設定・時間分布だけを扱う。
集計はメモリ内。保存する場合も数値だけにし、カメラ映像や個人の骨格を記録しない。
取得→結果→適用の時間は、身体動作→画面表示の遅延とは異なる。
