### 2026-09-30 右手の空中なぞり・銃の形・水平な横なでへ変更

ユーザーの追加指定で、縦軸のひねりによる視点と、押し込みによる攻撃を撤去。
**現在の操作はこの節を優先する。** 右手の上下なぞりとジャンプの競合を避け、
ジャンプは左の移動手を上げる動作へ変更した。設定の左右入替も全操作に反映する。

| 手 | 動き | 動作 |
| --- | --- | --- |
| 左（移動手） | 押す／引く・下げる／左右へ傾ける | 前進／後退／横移動。押しながら傾けると斜め |
| 左（移動手） | 初期位置より上げる | ジャンプ。下ろして次のジャンプ |
| 右 | 手を開き、空中を上下左右になぞる | 手の移動量だけカメラを動かす。止めると視点も止まる |
| 右 | 軽く握って位置を戻し、開き直す | 視点を動かさずに持ち替え。開いた位置が次の始点 |
| 右 | 親指・人差し指・中指を伸ばし、薬指・小指を曲げる | 攻撃。1回の構えで1回、指を開いてから次の構え |
| 右 | 手のひらを水平にして横へなでる | 近くの対象を撫でる・採取・調べる。片方向でも成立 |

- 指の3次元関節の曲がりと手首からの相対長から、各指を伸・曲・不明に分類。
  欠けた指先や不正なzは「不明」であり、曲げた指に数えない。銃の形は5指すべてを確認。
  左の移動は従来通り、指先が枠外でも掌が有効なら継続する。
- 視点は正面の開いた手、近接操作は水平の開いた手で分離。掌法線の垂直成分が0.72以上なら横なで、
  0.6未満かつ正面成分0.45超なら視点。境界では視点も近接操作も開始しない。
  法線は上下どちらの水平も受け付け、案内は手のひらを下へ向ける形に統一した。
- 銃の形を100ms確認して攻撃し、明確な別の形100msで再準備。未知の指や認識喪失は解除扱いにしない。
  再取得した銃の形は発火させない。横なでは基準幅0.22S、100ms以上、600ms間隔。往復や中央復帰は不要。
- 視点には70msの形確認、画像幅0.004の揺れ除去、55msの補間を使う。
  移動量を累積して描画側で差分を消費し、描画が認識より遅くても二重適用や移動量の取りこぼしを防ぐ。

- ジャンプは移動手を初期位置から0.28S上げて200ms確認、0.12S以内まで下ろして80msで再準備。

  描画待ちをなくし、古い結果の期限は延長しない。再度の描画でイベントを二重消費しない。
  メニューやフォーカス等の判定は同じ処理を通すため維持される。
- ゲーム内で認識した形、5指の伸曲、銃の形との一致、視点の動き、対象と実行結果を表示。
  右手の操作カードをカメラの横の先頭にし、仲間の操作案内も「横なで」へ更新。
  人物の向きとカメラの分離、左右入替、前進・後退・斜め移動、自動復帰、再開ボタンなしを維持する。

### 2026-09-30 動画で判明した停止条件の撤去と、視点・人物方向の分離

この時点の操作仕様は以下（右手ジェスチャー変更より前）。下に残した過去の「下げて休止」「両手を中央へ戻す」「人物方向に視点が追従」は、この変更で置き換えた。

| 手 | 動き | 動作 |
| --- | --- | --- |
| 移動手（既定は左） | 手のひらをカメラへ押す | 前進 |
| 移動手 | 引く、または基準の構えより下げる | 後退 |
| 移動手 | 手首を左右へ傾ける | 画面に対して左右へ移動。押し込みと同時なら斜め |
| 移動手 | 手のひらを縦軸にひねる | カメラだけが左右に回る。正面へ戻すと停止 |
| アクション手（既定は右） | 押す／上げる／左右に振る | 攻撃／ジャンプ／近くを調べる・拾う・撫でる |

提供録画の冒頭は、左手の大きさ167%・指先171%でも、下げた手首が休止閾値を超えたため前進しなかった。
約4.5秒・19.5秒・22.5秒・31.5秒には、両手の認識表示が緑でもRECOVERINGに固定されていた。
約25.5秒には128%の手でも「中央へ戻して移動を再開」が残っていた。認識器だけでなく入力側のゲートが操作を阻んでいた。

- 休止／再準備ラッチを撤去。前後の押し引きと下降、傾きを連続入力にする。押しながら手首が下がっても前進を優先し、急に後退しない。
- 手の相対的なzを局所的な傾き・回転の補正に使う。掌の縦横と指先までの長さを較正時と比較して押し引きを判断。指先だけが枠外の場合は見えている掌の縦横を使う。
  [MediaPipe公式Hand landmarks仕様](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/hands.md)の通りzは手首を原点とする相対値であり、カメラからの絶対距離ではない。worldLandmarksは使わない。
- 横移動は手首→中指根元の傾き、視点は掌の法線の横向きで別々に作る。較正からの角度差・不感帯・中央値で小さな揺れを抑える。初回復帰の単発スパイクも通さない。
- `MotionNavigation`は移動軸と視点の回転量だけを出す。メイン側で視点を回し、その視点に対する移動を既存の速度・衝突・同期へ渡す。静止時に人物のfacingを変更する命令は送らない。
- 230ms以上古い結果や両手喪失は移動と保留アクションを停止。新しく見えた手の2標本・45ms以上でその場から復帰する。両手の中央や指示ボタンは不要。短い認識途絶でセッションを変更しないため、処理中の次の有効結果を捨てない。
- アクションの再取得は押し込み／上げた姿勢を新しい動作に数えない。少し引いて次の攻撃、下げて次のジャンプができる。片手だけの復帰も受け付ける。
- 撫で中の小さな移動を抑えつつ、カメラ旋回は許可。新しい押し込み・引き戻し・下降・傾きで中断できる。
- パネルの移動表示を前後・横移動のベクトルにし、視点のひねりは別の青い目盛りにした。対象とアクション結果をカメラの下に出し、メッセージ更新で映像の位置が上下しないようにした。

検証は関連141テスト（10/15/20Hz・左右入替・167%＋下降・斜め移動・角度ノイズ・部分的な枠外・認識途絶・片手復帰・アクション再発火防止・撫で・人物の向きと視点の独立）、型/strictビルド。
提供録画からカメラ領域を切り出して鏡像を戻し、同梱CPU Workerで345フレームを再解析した。6〜9秒から両手を検出できた6.3秒の一コマを繰り返して初期較正し、10Hzの映像時刻で入力を再生した。これは**録画の再解析**であり、通常ゲームの描画負荷・推論遅延を含む実プレイの成功率ではない。
冒頭と18〜21秒の押し込みで前進入力、基準の再調整0回を確認。録画には骨格の線と縮小が含まれ、再認識の取りこぼしも残る。
縦軸旋回を含む修正後の実身体の連続操作感は未確認。原動画はDownloadsのまま、静止画・検証ページ・集計はignored `output/motion-video-review/`だけに保持した。映像の外部送信と実カメラの録画なし。

### 2026-09-30 攻撃・撫でる操作の成立条件と実行経路を修正

手が見えていても、アクションごとに較正時の小さな中央領域を通る必要があり、
速い押し込みは中央値と保持待ちを終える前に消えていた。手振りも中央の標本を
必須としたため、10～20Hzで中央を飛び越えた往復や手首固定の手振りが成立しなかった。

- `motion-actions.ts`でアクションを独立認識。攻撃は14%の拡大を45ms以上離れた2標本で確認。
  押し続けても1回だけ。ピークから10%引くか元の大きさの6%以内へ引くと2標本で再準備し、
  その位置を次の押し込み基準にする。XYの中央復帰は不要。単発の拡大・縮小ノイズは棄却。
- 手振りは手のひら中央関節の横移動0.16Sと折り返し0.14Sを1.2秒内で検出。
  中央を通る標本は不要。手首を固定した左右の傾きも対象。単方向移動・小さな揺れ・遅い往復は棄却。
  連続手振りは600ms間隔。ジャンプは上方向200msを保持し、攻撃との共通ロックを撤去。
- 片手の無効点・位置の不連続で両手をRECOVERINGへ送らない。
  指先が切れても手のひらが有効ならアクション手の移動を使う。拡大による攻撃は指先確認も必要。
  移動手の端抜け600ms＋300ms減速・両手喪失の停止・230ms期限切れ・イベント期限は保持。
- `motion-interaction.ts`で近くの撫でられる仲間を手振り対象の先頭にする。
  表示する対象名と送るコマンドを共有し、攻撃可能状態と認識した動作も表示。
  撫でる直前に移動を止め、その間の小さな揺れを抑える。明確な新しい押し込み・旋回を
  80ms以上の新しい標本で確認すれば中断する。未開始の要求は900msで解除し、セッションを跨がない。
- 524の喜ぶ動作が終わったらpetPlayerId等を消す。従来は終了後も残り、
  リモねこの操作受付を妨げていた。他の人が撫でている524を操作候補にしない。

10/15/20Hz・左右入替・部分的な引き戻し・中央外での手振り・手首固定・片手喪失と、
ゲームのリモねこ/524の処理を通した撫で完了を検証。関連132テスト、型/strict、398JS構文、依存境界を確認。
実カメラによる連続プレイの体験は未確認。結果 `output/motion-feel-tests.txt`。
3000番の既存起動は監視なしの単独Nodeだったため、Chromeの接続を一度閉じ、接続者0と新しい
自動保存成功を確認。保存2ファイルを配信外の`output/motion-feel-save-before-restart/`へ予備保存した。
PowerShellの停止APIが例外で失敗した後、同じPID7080・起動コマンド・ポート・保存を再照合して
Windows標準の停止コマンドで終了し、修正版を同じ保存先・3000番で起動。保存復旧なしで起動を確認。
保存セッション9件の人物・持ち物は一致。Chromeの通常の再入場操作により、MOTION-LIVEの人物位置は

### 2026-09-30 右手の攻撃と近接操作を押し込み・振り動作へ変更

ユーザー指定でアクション手の下方向の「休む」を撤去。移動手の休止は保持。
攻撃は移動手の前進と同じ、開いた手のひら幅・長さ・指先までの3尺度の拡大で判定する。
14%超の3標本中央値と120msの継続が必要で、押しっぱなしでは繰り返さない。
ジャンプは手を上へ動かして200ms保持する。調べる・拾う・撫でるは手を一方の横へ動かし、
中央を通って反対側まで1.2秒以内に振ると1回発動する。単なる横移動や遅い戻りでは発動しない。
各アクション後は中央へ150ms戻して再準備。左右の手を入れ替えても同じ動きで操作できる。
画面には攻撃手の拡大率ゲージ、ジャンプと左右の振りの案内を表示する。

型/strictビルド、モーション関連73テスト・396 JS構文・依存境界が成功。実身体の押し出し・振り動作での操作感は未確認。
映像・骨格保存なし、展示配布・公開デプロイ・commit/pushなし。

### 2026-09-30 実演で判明した復帰不能を修正

通常Chromeの実演中、手は左右21/21点、Hands CPUは約12回/秒で結果を返し、
手のひら/指先の倍率も更新されていたが、入力はRECOVERINGのまま前進・攻撃に入れなかった。
前回の較正位置から両手首の位置が変わると、元の位置への狭い復帰範囲に入らず、
手が安定して見えていても新しい基準へ合わせ直す経路がなかった。

復帰範囲を移動0.16S・アクション0.18S・手の大きさ±9%へ広げた。
そこに戻れない場合、RECOVERING/READY中に両手が800ms/8標本安定すれば基準を自動更新し、
さらに中央250msでACTIVEへ戻る。初期較正の手首/大きさの許容値も、実手の微動を考慮し
画像幅0.05/16%へ変更。1フレームの認識抜けは回復中の調整を消さない。
押し込みを保持した手は新しい停止位置として較正せず、操作中やPAUSED中も自動更新しない。
画面には再調整の進捗を表示する。

新規4件を含む関連69テスト、型/strict・依存境界・差分書式成功。
更新後のChromeでIntegrated Webcam 640×480とHands CPU稼働を確認。

### 2026-09-30 手専用モデルと手全体の拡大率で前進

ユーザーの「手首から指先までが大きく映ることで前進」と、添付の両手の構図に合わせて変更。
Pose Lite/肩に対する手首zを廃し、Hand Landmarker float16 v1で両手の各21点だけを使う。
顔・肩・肘・全身の検出は不要。手首から指先までの距離と手のひらの幅/長さの3比率から
前進を判定し、指だけを伸ばす動き・強い横向き・曲げた指を除外する。
較正時を100%、拡大14%で開始、7%へ戻ると停止、55%で最大。3点中央値＋開始120ms。
上下だけでは前進しない。これは画像内の相対尺度で、実距離や腕だけの運動の測定ではない。
身体ごと寄る動きとの完全な区別はできない。操作範囲は較正した手のひら幅を基準に固定する。

手のガイドを各21点の骨格へ変更し、顔/肩/肘の点は取得しない。
詳細は画面内の点数・推論時間・鮮度、移動欄は手の大きさ/手のひら/指先までの倍率を表示。
点ごとの信頼度を返さないモデルなので、緑色や21/21点を信頼度として扱わない。
左右の分類はTasksの出力をそのまま採用し、鏡像変換は座標だけに一回適用。
旧Solutionsの左右反転指示とTasksのラベル表の違いを公式ソースと添付画像で照合した。

画面端の継続600ms＋減衰300msは、もう片方の新しい手の認識がある場合に限定して維持。
両手喪失/期限切れ/中央での喪失は停止。中央250msで自動復帰し、手動再開へ固定しない。
メニュー/非表示/通信断等のPAUSED、単発アクション、入力所有権、資源解放の条件は維持。
