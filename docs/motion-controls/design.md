# 手だけのカメラ操作の設計

2026-10-05: 現行は[自動視点・左右旋回の試作](../assisted-controls-2026-10-05.md)と[右手／左手だけで遊ぶ片手操作](../single-hand-controls-2026-10-05.md)。下記は旧設計の履歴で、手動視点・枠外継続・基準の自動取り直しに関する記載は現行仕様に適用しない。

2026-09-30更新。元の要求は [移動した仕様書](../threejs_upper_body_motion_codex_prompt.md)。
ユーザーの追加指定を受け、現在は手専用モデルと画像内の拡大率を使う。
肩・肘・顔・全身の認識は不要。以前のPose/推定z方式は実装記録に履歴として残す。

## 構成と既存ゲームへの接続

motion-camera.ts（カメラ・世代・転送制限）→ motion-worker.ts（Hand Landmarker）→
motion-hands.ts（21点の抽出・画像内の計測）→ motion-input.ts（較正・状態機械・入力）→
main.ts（既存ゲーム操作）。UIはmotion-controls.ts、骨格と認識状態はmotion-debug-view.ts。

既存構成はthree 0.185.1、TypeScript 6 / NodeNext、DOM/CSS/ES Modules。
Workerはページのimport mapへ依存しない。描画は既存WebGLRenderer/FrameClockの最大60Hz。
移動はMovementCommands→application/game-core→shared/movement、攻撃・ジャンプ・近接操作は
既存action経路へ渡す。速度・衝突・命中・再使用待ち・攻撃中の制約・同期は共通のまま。
認識層はMeshを直接操作せず、映像・骨格をWebSocketへ送らない。

Workerは両手の各21点のx/yと左右分類スコアだけを返す。
z、worldLandmarks、身体や顔の点を操作層へ渡さない。
Tasks HandLandmarkerのLeft/Rightをそのまま使用し、X座標は表示/入力時だけ一度鏡像化する。
旧Solutions Handsの左右反転指示を流用しない。Tasksのラベル表はRight/Left、
旧SolutionsはLeft/Rightで異なる。添付の鏡像プレビューを一度戻して実モデルで照合した。

## 前進の測定

開いた手を楽に構えた位置で、手首位置と次の3尺度の中央値を較正する。
距離はsqrt(dx²+(dy×画像高さ/画像幅)²)で画像の縦横比を補正する。

- 手のひらの幅：人差し指付け根5から小指付け根17。
- 手のひらの長さ：手首0から中指付け根9。
- 指先までの長さ：手首0から人差し指8・中指12・薬指16の各距離の中央値。

現在値をそれぞれ較正値で割り、3比率の最小値−1を押し出し量にする。
3本以上の指が伸びており、手のひらの縦横比が範囲内で、3比率の最大/最小が1.35未満のときだけ有効。
指先だけ伸びても手のひらが大きくならないため前進しない。指を曲げる・強く横向きにする動きも除く。
手首・付け根・主要な指先が画面外/非有限の場合は操作用の手を無効にする。
これは画像上の相対拡大率であり、物理距離ではない。身体ごとカメラへ寄る場合も拡大する。
単眼画像だけではそれと腕だけの押し出しを完全には区別できない。

左右旋回・ジャンプ・振り動作は較正時の手首からのXY移動を使う。攻撃は移動手と同じ3尺度の拡大率を使う。
基準尺度S=clamp(左右の手のひら幅の和×1.5, 0.18, 0.48)を較正時に固定し、
押し出した手の大きさで途中の操作範囲が変わらないようにする。
左手が移動、右手はカメラへ押して攻撃・上でジャンプ・左右に振って近接操作。設定で入れ替え可能。
移動手を下げると休止し、元の位置へ戻して再準備する。アクション手を下げる休止操作はない。上へ上げるだけでは前進しない。

## 初期値（実利用者による最適値ではない）

| 項目 | 値 |
| --- | --- |
| モデル | Hand Landmarker float16 v1、tasks-vision 1.0.1、VIDEO、numHands=2。検出/存在/追跡のモデル設定は各0.5。左右分類が0.55未満または同じ左右の重複は採用しない。 |
| 推論 | CPU Worker、15Hz上限、同時Bitmap1件。設定でCPU/GPU・10/15/20Hz・映像のみ。 |
| 映像 | 640×480 / 30fpsのideal指定、音声なし。アスペクト比保持。 |
| 較正 | 連続1,400ms以上かつ10標本以上。両手XYの変動は画像幅の0.05以内、移動手のひら幅/長さの変動は16%以内。移動手の指を伸ばす。 |
| 前進 | 拡大14%で開始、7%で解除、55%で最大。直近3点の中央値と開始120ms。元へ戻した生値でも即停止する。 |
| 復帰 | 元の構えに近ければ両手を250ms止める。移動手XYは0.16S未満、拡大率差は±9%未満、アクション手XYは0.18S未満。以前と違う構えでも、開いた両手が800ms/8標本安定したら新しい基準に合わせ、そこから250msで操作へ戻る。1フレームの認識抜けは230ms内なら再調整を破棄しない。押し込みを保持した手は新基準に採用しない。 |
| 旋回/休止 | 旋回開始0.10S、解除0.065S、最大0.42S。下0.34Sで休止。逆進なし。旋回最大1.5rad/s。 |
| アクション | 攻撃は手全体の拡大14%・3標本中央値・開始120ms。ジャンプは上0.22Sかつ主軸優勢1.15倍・確定200ms。近接操作は横0.20S→中央0.12S未満→反対側0.20Sの往復を1,200ms以内。中央150msで再準備。保持中の再発火なし。 |
| 期限 | 取得から230msで入力/イベント失効。40ms監視＋通常70ms更新下で300ms以内を狙う。停止中のJSの実時間保証ではない。 |
| 手の喪失 | RECOVERINGで停止し、両手の中央250msで自動復帰。長い喪失でも手動再開へ固定しない。 |
| 画面端 | 直前の移動手のいずれかの点が上/左右18%以内で、230ms内に移動していた場合のみ600ms維持＋300ms減衰。反対の手の新しい認識が必要。両手喪失、下への休止、中央での喪失、期限切れは停止。 |

操作中にニュートラルを追従させない。見失った後のRECOVERING/READY中だけ安定した位置へ合わせ直す。
座り直した直後に合わない場合は両手を楽な位置で約1秒止める。設定の「手の位置を合わせ直す」も使える。
大きな手位置の不連続はRECOVERINGへ。手だけでは本人識別できず、二人の左右の手を組み合わせる可能性がある。
numHands=2は一人限定の保証ではない。本人識別、顔認証は追加していない。

## 表示

鏡像映像に手首から指先まで42点・42本の接続線と左右ラベルを重ねる。
古い結果、画面外の点、未検出は残さない。SVGを再利用し、映像DOMを作り直さない。
詳細欄は左右それぞれ画面内の点数、映像/モデル/入力状態、結果の鮮度・推論時間・頻度を表示する。
HandLandmarkerは点ごとの信頼度を返さないので、21/21点や緑色を認識精度・確信度と呼ばない。
手の大きさ100%が較正位置。手のひらと指先までの比率を別々に表示する。
アクション手にも攻撃用の手の大きさゲージを表示し、左右の振りは1回の方向転換だけでは発火させない。
形が合わないときは指と手の向きを案内する。攻撃成功とゲーム側の空中/乗り物/再使用待ちを区別する。

## 入力所有権とリソース

STARTINGから終了までカメラが移動/視点/アクションを所有する。キーボード/ゲームパッドと加算しない。
メニュー、フォーカス喪失、非表示、接続断、ダウン、人物/乗り物/ワープ変更はPAUSEDで即停止。
操作可能な画面・通信・映像が戻ればREADYへ自動遷移し、両手の中央250msまたは安定した新位置への再調整後にACTIVEへ戻す。
保持中の動作や古いアクションは再生しない。カメラの開始と終了は引き続き明示操作。
カメラ欄内のチェック等へのフォーカスは停止させない。タイトル/離脱/通常操作への復帰で解放する。
MotionHeadingは開始/再開時の視点の前方向を採用し、以後は独立したワールド方向を持つ。
その場旋回は既存moveメッセージの任意facingで共有。所有権・攻撃ロック・500msサーバー入力期限を維持。

sessionId、単調frame/eventId、取得/発行時刻で古い結果・重複・逆順を捨てる。
アクションは最大1件を一度だけ消費する。反対の手の喪失中は未確認アクションを発行しない。
明示開始後だけカメラ/Worker/ローカル資材を取得。requestVideoFrameCallbackと監視タイマーを使い、
busy中は未取得の映像時刻を消費せず、推論終了後に上限Hz内で最新映像を取得する。
Bitmap生成前からbusyとし、Workerのfinallyでclose。終了時にtrack/callback/timer/listenerを解放、
モデルcloseを待ち250msでWorkerを終了する。遅れた許可のストリームも停止する。
初期化30秒、映像無更新10秒、推論応答5秒の監視を保持する。
集計は最大600件/指標、骨格は最新結果と較正に必要な短いメモリのみ。映像・骨格の送信/保存なし。
