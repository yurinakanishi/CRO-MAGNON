# 検証と展示前の確認票

## 現行の検証

```powershell
node scripts/prepare-vendor.mjs
node scripts/build.mjs
node --test tests/motion-input.test.mjs tests/motion-hands.test.mjs tests/motion-debug.test.mjs tests/motion-camera.test.mjs tests/motion-assets.test.mjs tests/combat-input.test.mjs
node scripts/check-syntax.mjs
node scripts/check-architecture.mjs
```

両手各21点の合成入力と仮想時刻を使う。身体・z/world座標を参照しないこと、
10/15/20Hzでの拡大とノイズ、指だけの伸展、手の向き、停止/復帰、アクション単発、左右入替、
カメラ資源解放、古い結果、ローカルモデルのSHAとMIME/CSPを確認する。
これらは実利用者の認識率や疲労の証明ではない。

2026-09-30の実演で、実カメラは両手各21/21点を認識しているのにRECOVERINGから進まず、
以前の構えへの復帰条件が原因と確認した。安定した新しい構えへ自動調整する修正を追加し、
短い認識抜け、押し込みを保持したままの誤較正防止、移動中の再調整防止、PAUSEDの明示再開を
関連69テストで確認した。Chromeを修正版へ更新してカメラ稼働を確認。更新後の身体動作は検証中。

ユーザー添付の559×439静止画をloopbackだけで既存ファイルから読み、
本番Worker/Hand Landmarker CPUで両手の各21点、開いた手、較正→ACTIVE、左右ラベルを確認した。
画像を複製・保存・外部送信していない。結果の骨格もファイル保存しない。
静止画での認識成功は実身体の押し出し動作の成功率とは区別する。

CUAでローカルの合成入力ページを操作し、実画面のゲージ・骨格・入力・復帰を確認する。
検査ページは実カメラでないことを常時明記する。数値と実施項目だけをoutput/motion-handsに記録する。
ゲームの実カメラ画面を証拠として保存しない。

CPU/GPUと10/15/20Hzは同じ場面/画質でOFF・映像だけ・認識ONを比較する。
描画中央値/p95、50ms超、推論/実効Hz、ドロップ、取得→結果→適用、起動時間を分ける。
確定200msや前進の3点中央値＋120msと、身体動作→表示の実測を混同しない。
過去の性能記録はPose版であり、今回の手モデルの負荷/精度の代わりにしない。
実機での仮の目標はOFF比描画中央値悪化10%以内。達成済みではなく、操作成功率と合わせて判断する。
