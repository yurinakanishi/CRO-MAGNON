# 衝突時にプレイヤーの向きが変わる不具合

2026-09-09、ユーザー指定で修正。

原因は二つ。共有移動処理が衝突後の実移動量から向きを更新し、描画処理も位置補間・押し出しの移動量から再び向きを計算していた。このため、壁沿いの横滑りや敵による押し出しが左右への旋回として表示された。

`movePlayer` は有効な方向入力から向きを決め、無入力・入力期限切れでは直前の向きを保持する。完全に阻まれている間も新しい入力へ向きを変えられる。描画はサーバー／ローカル予測の facing に追従し、位置補正を向きへ変換しない。衝突の押し出し・速度・歩行／走行判定は保持。AI用 `moveActor` は従来通り実移動方向へ向く。共有処理を使う手動騎乗・操船にも同じ入力方針を適用する。

検証:

- 全428テスト通過（新規5件）。壁沿いの歩行・走行、完全停止から離脱、敵の押し出し、無入力・期限切れ、予測とサーバーの一致、AIの向きを検査。
- strictを含むビルド・型検査、228 JS構文、依存境界、変更ソースの書式を確認。
- `node scripts/qa-collision-facing.mjs` で分離した実Chromeの通常UIを起動。既存テントへ実キーで移動し、予測OFF／ONの滑りを確認。実敵の接触による0.1801mの押し出しを確認。計248描画観測で意図した向きとの差0、ブラウザーエラー0。画像3枚を出力し、テントと敵の画像を確認。
- 接触開始位置・カメラ・敵の位置とAI待機は準備値。移動と衝突は実時間。時計変更なし。全外見・全地形・実コントローラー・長時間負荷は今回未検証。

通常3000番への反映:

- 最初のPowerShellポート取得が空だったため停止中と誤認。追加起動PID58004は保存ロックで失敗し、既存PID40396は継続した。
- `netstat` とプロセス開始時刻でPID40396（22:59:52）の通常サーバーを特定。loopbackのNode inspectorでPID・cwd・起動ファイル・既存SIGINTハンドラーを照合し、そのハンドラーを呼んで入力とtick停止→最終保存→正常終了した。強制停止なし。
- 23:13:04の最終保存後に通常 `node server.mjs` を非表示起動、PID43292へ切替。最新保存の1部屋と再開情報を読込み、自動保存正常・予備復元なしを確認。
- 通常Chromeのタイトル起動、2メニュー、修正した2配信ファイルのバイト／SHA一致を確認。既存ユーザーの画面は再読み込みで新しい描画処理を取得する。
