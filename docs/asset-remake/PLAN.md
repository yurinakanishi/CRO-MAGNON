## 2. 目指す見た目（制作方針）

既存の参照画像群（マンモス・人物・テント等）と現在のゲーム画面から整理した画風:

- **原始時代＋穏やかなファンタジー**の「絵画的リアリズム」。実在の氷河期の素材感（毛皮・獣皮・骨・石・木・土）を、読みやすい大きな形と抑えた細部で描く。写実的な汚れやノイズは足さない。
- 色: 黄土・赤褐・焦茶・苔緑・骨白を基調に、仲間・ファンタジー要素（猫耳・砂耳・丸いbot・白羽教団）だけ固有色を保つ。
- 形: 遠景でも種類が分かるシルエット（マンモスのドーム状頭部と肩の瘤・牙、人物のマントと腰帯、テントの交差した支柱）を最優先。顔・手・牙・耳・尾・縫い目など対象らしさの細部は高密度面から法線マップへ焼き込む。
- 素材差: アルベド（TRELLIS）＋法線（高密度面からベイク）＋粗さ（TRELLISのPBR粗さを素材ごとに制限）で、毛・皮・石・木・骨の反射の違いを出す。金属度は全て0。
- ゲストキャラクター（524・りもねこ・まるぃも・こはく・mae・Howkey・丸いbot）は承認済みの原画像・既存モデルの輪郭・配色・非対称な特徴を基準にし、画風統一のために別物にしない。

## 3. 制作方法（全対象共通の工程）

`参照画像（Codex built-in image_gen、旧参照を添付して同一性を保持）→ TRELLIS-2 v0.8.1（res 1024・tex 1024・seed 42、BiRefNet）→ 高密度面の目視（中立照明・多方向）→ scripts/remake/remake_process.py（剛体配置・一様縮尺・浮遊片除去・予算付きQEM・高密度面からの法線ベイク・PBR粗さ・WebP/タンジェント付きGLB・LOD）→ リグ／動作（対象別）→ 書き出しGLBの再読込QA → ゲーム組み込み → 実プレイ検証`

- 1モデル1候補（各ワークスペースの次番号＝原則Candidate 2）。作業は `output/model-generation/models/<key>/work/candidate-02/`、旧候補・旧配信GLBは全て保持し、新GLBは別名（`model-c2.glb` 等）で配信。
- TRELLISはGPU 6 GBのため `scripts/remake/trellis_queue.py` で直列実行（他セッションの `world-trellis.lock` を尊重）。Blenderの重い処理は Cycles CPU で行いGPUと競合させない。
- 可視モデルをプリミティブや手続き生成で作らない（`MODELING_WORKFLOW_POLICY.md`）。高密度面に問題があれば参照画像・seed・条件から作り直す。

## 4. 予算（対象の重要度・画面上の大きさから決める上限。実測で調整）

| 区分 | 近景三角形 | テクスチャ | 骨 | 備考 |
|---|---:|---|---:|---|
| プレイヤー（同時5＋住人8＋NPC） | 45k〜70k | アルベド2048・法線2048・粗さ1024 | 22〜28（触手75） | LOD 28 m（既存） |
| 大型動物・敵（マンモス・大虎・巨獣・カラス） | 30k〜50k | 2048/2048/1024 | 20〜30 | カラスは28体同時→LOD必須 |
| 仲間（0.25〜0.55 m） | 8k〜25k | 1024/1024/512 | 既存構造 | 45bot同時 |
| 装備・資源・小物 | 2k〜12k | 1024/1024/512 | 0 | インスタンス数に応じLOD |
| 建物・野営地の構造物 | 10k〜40k | 1024〜2048 | 0 | |
| 植生（インスタンス） | 1k〜15k＋LOD | 512〜1024 | 0 | 既存インポスター併用 |
| 地形・水面タイル | 現状維持〜10k | 1024 | 0 | 歩行データと整合 |
| ランドマーク（城・洞窟・山） | 既存の歩行データ依存 | 2048 | 0 | 歩行・カメラ用の計測データを再生成 |

目標: 変更前と同じ測定条件で、キャンプのフレーム三角形数と読込量を減らしつつ（フレーム時間を悪化させない）、外観の比較で明確に改善すること。

## 5. 進め方

1. 代表3体（四足＝マンモス、人型＝クロマニョン人男性、静物＝獣皮のテント）で、参照→復元→処理→リグ／動作→ゲーム組み込み→比較を一通り完成させ、品質基準と手順を確定。
2. 確定した手順で残りを順次。GPUキューを常に回し、CPU側でリグ・組み込み・検証を並行。
3. 各対象の進捗・問題・検証結果を `assets/asset-remake/status.json` に記録し、INVENTORY.mdを再生成。区切りでは完了／未完了と次の作業を [PROGRESS.md](PROGRESS.md) に残す。
