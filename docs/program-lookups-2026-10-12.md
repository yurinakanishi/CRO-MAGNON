# 毎フレームのシェーダープログラムの選び直しをなくす（2026-10-12）

カメラの修正（[camera-clearance-2026-10-12.md](camera-clearance-2026-10-12.md)）の検証で取ったCPUプロファイルで、three.js r185の `WebGLRenderer.setProgram → getProgram → getParameters` が毎フレーム動いていた（変更前のビルドでも同じ）。ユーザーの指示で、どの材質が毎フレーム選び直されているかを確かめてから原因を直した。見た目・モデル・GLBの変更はない。

## 観測の方法

`scripts/qa-program-lookups.mjs`（新規）：QAと同じメモリだけのLOCAL_VERIFYサーバーで、配信する `three.module.js` を転送時に書き換え、`setProgram` が `needsProgramChange = true` とする26の分岐それぞれから理由・材質・物体を報告させ、`getProgram` の時間を測る。`qa-camera-clearance.mjs` と同じ3か所（キャンプのトウヒの裾 tree0-skirt、洞窟の壁 cave6R・cave-21L）で、カメラを90°/sで回して90フレームずつ数える。変更前は `41a4f09`（HEAD）、変更後はそれに今回の変更だけを加えたビルド（どちらも `git archive` から作り、`--browser` で配信）。

## 原因

変更前の1フレームあたりの選び直し（90フレームの平均、すべてのフレームで発生）：

| 場所 | 選び直し／フレーム（最大） | 材質の版が変わった | インスタンスの切り替え | 光源の構成 |
| --- | --- | --- | --- | --- |
| tree0-skirt | 23.1（42） | 19.3 | 3.8 | 0.01 |
| cave6R | 24.0（48） | 19.7 | 4.2 | 0.03 |
| cave-21L | 17.0（56） | 12.2 | 3.9 | 0.9 |

1. **透明で両面の水**：three r185は `transparent` かつ `DoubleSide` の材質を裏面→表面の2回に分けて描き、それぞれの前に `material.needsUpdate = true` とする（`WebGLRenderer.renderObject`）。描くたびに材質の版が変わり、プログラムを2回選び直す。対象は川の水面21枚（1つの材質を共有、`world-scenery.ts`）、ベヒーモスの沼6つ、洞窟の泉（`cave-spring.ts`）。見えている川1枚につき2回（キャンプで川を見渡すフレームは選び直しが合計40回前後）。山の川・湖は以前から `forceSinglePass`（1回描き）で対象外。
2. **インスタンスと通常のメッシュで同じ材質**：three r185は材質ごとに今のプログラムを1つだけ持ち、インスタンス描画かどうかもプログラムの一部。同じフレームで両方に使われる材質は、切り替わるたびに選び直す（r185は同じ材質の描画をインスタンスかどうかで並べるので、材質ごとに1フレーム2回）。観測したのは地面（草原 `Material_0`、雪、砂漠）：川岸にかかる区画は地面の材質を通常のメッシュで描き（`open-world.ts`）、ほかの区画は同じ材質のインスタンス。洞窟では薪の山（インスタンス、`wood-pile.ts`）と手に持つ松明の薪（`firewood-log` のLOD1の通常の複製、`cave-torch.ts`）。
   ユーザーが疑った `LandscapeInstances` も同じ型：木・岩のインスタンスはテンプレートの材質そのもので、同じテンプレートの通常の複製（資源・置物、地域の表面の置物、`coastal-renderer.ts` の石台）と同じフレームに描かれると同じことが起こる。今回の3か所では起きていなかった。石の山・貝・畑の境界石（`stone-pile.ts`・`coastal-renderer.ts`・`gulf-renderer.ts`）も同じ作り。

## 変更

新規 `src/material-variants.ts`：

| 関数 | 内容 |
| --- | --- |
| `materialCopy` | 材質の複製：`clone()` に、それが落とす自前の関数（`onBeforeCompile`・`customProgramCacheKey` など）を引き継ぎ、`userData` は同じオブジェクトを共有し、`defines` を写す。`performance-lod.ts` の `compatibleMaterial` が持っていた処理を移し、そちらもこれを使う。 |
| `instancedMaterial` | インスタンス描画用の複製。元の材質1つにつき1つで、インスタンスの利用者すべてが共有し、元の材質の `dispose` で一緒に解放される。通常のメッシュは元の材質のまま。使用箇所：`LandscapeInstances`（草以外。草は以前から専用の複製）、`wood-pile.ts`、`stone-pile.ts`、`coastal-renderer.ts`（貝）、`gulf-renderer.ts`（境界石）、`open-world.ts`（地面のタイル。川岸の通常のメッシュは元の材質）。 |
| `drawSidesInTurn` | 透明・両面の2回描きを、ジオメトリ全体を指す2つのグループと、裏面用（`BackSide`）・表面用（`FrontSide`）の材質の組で描く。プログラム・uniform・順序はthree自身の2回描きと同じ（1つの物体の同じ深度の2項目は、透明物の安定ソートで順序を保つ）。`renderer.compile()` は両方を準備する。川の水面21枚、沼6つ（テンプレートのバッファの複製1つを6つで共有）、洞窟の泉に使う。 |

`forceSinglePass`（両面を1回で描く）は使わなかった：さざ波のある水面では、視線がかすめる角度で裏向きと表向きの三角形が重なり、描く順が変わりうるため。

## 検証

**選び直しの回数**（`qa-program-lookups.mjs`、各90フレーム）：

| 場所 | 変更前 | 変更後 | 選び直しのないフレーム |
| --- | --- | --- | --- |
| tree0-skirt | 23.1／フレーム（最大42） | 0.36（最大5） | 0/90 → 76/90 |
| cave6R | 24.0（最大48） | 0.09（最大3） | 0/90 → 86/90 |
| cave-21L | 17.0（最大56） | 1.19（最大31） | 0/90 → 76/90 |

変更後に残るのは、初めて見えた材質・人物の初回の描画（プログラム数がtree0-skirt 52→53、cave6R 79→84、cave-21L 104→112と増える場面）と、cave-21Lの光源の構成の変化（下記）だけで、どちらも変更前と同じ回数ある。計装した `getProgram` の時間は1フレーム平均で0.91／1.06／0.66ms → 0.11／0.11／0.30ms（残りは同じ初回生成と光源の変化）。

**CPUプロファイル**（`qa-camera-clearance.mjs --only tree0-skirt,cave6R,cave-21L --profile --cost-only --browser <build>`、変更前・変更後を交互に3組、1フレームあたりのinclusive ms の平均。ヘッドレスChrome 154、ANGLE D3D11、Intel Iris Xe、1280×800）：

| 場所 | getProgram | getParameters | setProgram | WebGLRenderer.render | WorldRenderer.render |
| --- | --- | --- | --- | --- | --- |
| tree0-skirt | 0.436 → 0 | 0.221 → 0 | 1.343 → 0.803 | 2.980 → 2.360 | 4.578 → 3.774 |
| cave6R | 0.403 → 0 | 0.193 → 0 | 3.914 → 3.599 | 5.290 → 5.086 | 6.885 → 6.855 |
| cave-21L | 0.407 → 0 | 0.159 → 0 | 4.089 → 3.507 | 5.578 → 4.941 | 7.848 → 6.944 |

変更後のプロファイルには `getProgram`・`getParameters` が1サンプルも出ない。QAの `cost` の中央値（`simulationMs`）は `renderer.render` の前で測り終えるため、この変更の効果は出ない（変更前1.37〜1.83ms、変更後1.23〜1.73ms、揺れの範囲）。

**見た目**（実GPU、`qa-program-lookups.mjs --pixels`）：ゲームの更新を挟まない1回の評価の中で、変更後の描画と、組を1つの両面の材質に戻した描画（three自身の2回描き）を `readPixels` で比べた。川（キャンプ・橋の近く）・洞窟の泉・沼の4か所×8方向×2仰角＝64視点のうち、水が写る55視点（最大14.6万画素）で差は0画素。インスタンスの複製を元の材質に戻した比較も、地面・木・岩のインスタンス16〜24個（描画中3〜8個）で差0画素。同じ描画の繰り返しも差0。

**世界の準備**：`worldPreparedPrograms`（準備の描画が `compile` 以外に必要としたプログラム）は変更前後とも0。

**テスト**：新規 `tests/material-variants.test.mjs` 5件。three r185の `WebGLRenderer` を偽のWebGL2で動かし、変更前の作りでは選び直しが2回／フレーム（インスタンスと通常の共有）・8回／フレーム（両面の水4枚）あること、変更後は0回で、GLの描画の列（プログラム・表裏・順序）が同じことを確かめる。既存テストの更新：`wood-pile`・`stone-pile`（バッチの材質はインスタンス用の複製）、`fixed-water-placement`（水の裏面・表面の材質が時間のuniformを受け取る、2回描きの材質が残らない、沼は自分のバッファ）、`verified-texture`（ギャラリーの洞窟の材質探しが複数材質のメッシュを扱う）。全1,522件中1,518件合格・失敗0・4件条件付き未実行（Pillow・ベンチマーク）、`npm run check`、変更ファイルのPrettierに合格。

## 残っていること・未検証

- **光源の数の変化**：焚き火の点光源はカメラから65m以内のときだけ点ける（`world3d.ts` の `fire.light.visible`）。洞窟の奥（cave-21L）でカメラが回ると、見えている光源が3↔4と変わり、そのたびに見えている材質約30個が選び直し、初めての構成では新しいプログラムをコンパイルする。プロファイルでは洞窟の2か所で `WebGLProgram.onFirstUse`（初めてのリンク）が変更前後とも1フレーム平均2.4〜3.0ms（キャンプは0）。今回は変更していない（別作業として提案）。
- 一時的な効果（カラスの祈りの封印の膜・輪、水の中を歩いたときの波紋）は透明・両面の2回描きのまま（表示中だけ選び直す）。
- 実スマホ・他のGPUは未検証。数値はこのPCのヘッドレスChromeのもの。
- 既存の3000／8787／4173、ユーザーの保存、公開、展示配布、commit／pushの操作なし。
