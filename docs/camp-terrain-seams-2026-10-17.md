# キャンプ付近の地形の継ぎ目（2026-10-17）

ユーザーの「キャンプ付近の地面が直線で切れ、絨毯がめくれたように見えるので修正してデプロイ」に対応。

## 再現と原因

11:25の公開候補 `output/production-20261017-04/` を使い捨てのソロ環境で読み込み、通常の開始操作で再現した。キャンプの足元に鋭い多角形の色境界、洞窟への道に切れ端状の境界、草原の32mタイルの端に直線が出ていた。

- 草原は各タイルの元UVと90度単位の回転で模様を表示し、山は世界座標で画像を3方向から混ぜていた。両GLBの埋込画像は同一だが、重なったところで模様が切り替わっていた。
- 道と洞窟前の土色も、草原と山で別のマスクを使っていた。
- 草原GLBは厚みのあるタイル。上端の元法線に垂直な側面の向きが混ざり、平坦な上面の端だけに濃い影ができていた。実際の辺の高さは接続していた。

## 修正

`src/meadow-surface.ts` に草原と山で共有する世界座標の画像サンプリングと道の色付けをまとめた。山と草原の粗さも揃えた。画像・GLBは従来の検証済みTRELLIS由来素材を継続使用する。

地面の法線は実際の上向きの三角形から計算し、側面の法線が混ざらないようにした。通常タイルと川岸の変形後のタイルに適用する。位置・三角形の索引・UV・衝突判定・歩行の高さ・山の変形・洞窟開口・海岸の処理は変更していない。新しい可視モデルや代用地形は作っていない。

## 対象検証

- Windows / Node.js 24.15.0 / Chrome 154.0.8037.93。PC 1440×900、タッチ相当390×844。
- 実際の配信GLBを読み、上下の面を測定。4方向の回転同士、計16組の隣接を確認し、最大高さ差は **0.00000461m**。修正後の上面法線の傾きは最大 **0.310度**。位置・UV・三角形の配列が変わらないことも回帰テストで検証。
- `tests/meadow-seams.test.mjs` 2件合格。草原と山の実配信画像の同一性・繰り返し指定も検証。
- 既存の草原配色・海岸・山の表面・洞窟・歩行に関する24件も合格。
- 同一カメラと光で、実際の草原と山の重なる平坦部を別々に描画して比較。PCのRGB差の平均は修正前 **42.356/255**、修正後 **0.024/255**、修正後の最大差は1。スマホ相当でも平均0.030、最大1。
- タイル辺の隣接2列のRGB差は、PCで修正前5.625から修正後0.736へ。スマホ相当は修正後1.131。通常画面・上空からの確認・洞窟への道を画像で確認した。
- 通常のSキーでキャンプから約7.1m、スマホ相当のタッチパッドで約19.9m移動し、接続部を通過。位置の書き換えではなく実入力を使用。ブラウザー例外・ゲームAPI・WebSocketは0。

`scripts/qa-camp-terrain.mjs` は、開始操作と歩行は実UI、比較画像だけ固定カメラを使う。地面の分離表示は原因切り分けと画素比較用であり、通常プレイの証拠と区別する。初回のスマホ固定カメラ検証では、通常カメラの間引かれた可視範囲が残り片側の地面が消えた。観測用カメラに可視範囲を合わせる手順へ修正し、同じ候補で再実行して合格した。実スマホ・ネイティブSafari・物理パッド・長時間性能は未検証。
