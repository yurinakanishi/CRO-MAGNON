# 普段使っているPCを展示に出すときの安全対策

記録日: 2026-09-09。PC1・PC2共通の方針。
これは対策案と導入時の確認手順であり、キオスク設定を実施済みという記録ではない。
ゲームの起動・LAN接続手順は [README-EXHIBITION-NOW.md](README-EXHIBITION-NOW.md) を参照。

## 目的と現在の状態

来場者がゲームを遊べるようにしつつ、普段のデスクトップ、個人ファイル、
保存済みパスワード、メール、開発ツールへアクセスすることを防ぐ。

- PC1はレジストリのEditionIDが `Core` で、Homeエディションと確認済み。
- PC2のWindowsエディションは、この安全対策の検討では未確認。
- 展示専用ユーザー、Windowsのキオスク制限、専用ユーザーでの自動起動は未設定。
- 現在のLANゲームが起動することと、来場者向けの端末制限ができていることは別の確認。

## HomeとProでの選択肢

| 方法 | できること・限界 |
| --- | --- |
| Homeのまま、展示専用の標準ユーザー＋Edge全画面キオスク | ブラウザーの操作を制限し、誤操作を減らせる。ただしOSへの退出を完全には防げない |
| Pro以上で、展示専用ユーザー＋Windowsの「割り当てられたアクセス」 | 使用できるアプリをゲーム用Edgeに制限する構成が可能。今回の目的に推奨 |

Windows標準のAssigned Access（割り当てられたアクセス）はPro、Enterprise、
Education、IoT Enterpriseが対象で、Homeは対象に含まれない。
[Microsoft公式：Assigned Access](https://learn.microsoft.com/en-us/windows/configuration/assigned-access/)

Edge単独の全画面キオスクと、Windows側のアプリ制限は別の機能。
EdgeのキオスクにはF11・F12などの制限があるが、ファイルの「開く／保存」ダイアログは
自動ではすべて制限されない。対応するショートカットや印刷・ダウンロード・遷移先も確認する。
[Microsoft公式：Edgeキオスクの機能と制限](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-configure-kiosk-mode)

Proへの変更は有料となり得るため、購入・変更はまだ行っていない。
OS機能で制限しても、電源操作や物理的な機器へのアクセスまで完全に防げるわけではない。

## 導入する構成

1. 展示専用のローカル標準ユーザーを用意する。管理者権限は与えない。
2. 普段のアカウントはサインアウトし、管理者の認証情報はスタッフだけが管理する。
3. ゲームの配布データだけを、展示用の配置先へコピーする。
   個人のDesktopやプロファイル全体に閲覧権限を与えて動かす方法は使わない。
   個人フォルダー、共有フォルダー、別ドライブのアクセス権も確認する。
4. 展示用Edgeで `http://localhost:4173/?room=EXHIBITION` を開く。
   展示ユーザーでは個人のMicrosoftアカウントやブラウザー同期へログインしない。
5. ゲーム外へのリンク、ファイルを開く操作、保存、印刷、ダウンロードなどを制限する。
   必要なlocalhostとLAN同期通信を許可した状態で実ゲームを確認する。
6. スタッフ用にキオスクからの終了、管理者への切り替え、ゲーム再起動の手順を用意する。
   スタッフが復旧できることを確認してから来場者に渡す。
7. コントローラー展示なら、キーボードと管理用マウスを来場者の手が届かない場所に置く。
   ノートPC内蔵キーボード、電源ボタン、空きUSBポートへのアクセスも配置で管理する。

## 今回のLANゲームで必要な調整

展示ユーザーへ切り替えても、各PCのローカル配信サーバーが動く必要がある。
PC1では共有ゲームサーバーも動かす。

| PC | 裏で動かすもの | 表示するもの |
| --- | --- | --- |
| PC1 | localhost:4173のローカル配信＋0.0.0.0:8081の共有サーバー | ゲーム用Edge |
| PC2 | localhost:4173のローカル配信 | ゲーム用Edge |

現在のPC1は普段のユーザーの配布フォルダーから起動している。
PC2の手動実行用タスクも現在のYURIのログインセッションに依存している。
そのため、**展示ユーザーを作るだけでは完成しない**。
専用の配置先・必要最小限のアクセス権・バックグラウンド起動を整え、
普段のユーザーがサインアウトしていても動作する構成にする。
サーバーに管理者権限を与える前提にはしない。

LANのIP、部屋コード、同一ビルド、各PCでのGPU描画という構成は継続する。
両PCのWebSocket接続先は `ws://10.10.10.1:8081`。
ゲーム用FirewallはPrivateの直結LANに限定する。
Wi-Fiを切ることは通信経路の制限であり、個人ファイルへのアクセス制限の代わりにはならない。

SSH鍵はユーザーの既存指示どおり残す。
PC1の秘密鍵を展示ユーザーへ渡さず、管理者・普段のユーザー側で管理する。
ゲームの展示起動にSSH認証やWindowsのPIN入力を要求する構成にはしない。

## 展示前に行う実機確認

- 普段のユーザーをサインアウトし、展示ユーザーだけで起動できる。
- 両PCでLAN: Connected、部屋EXHIBITION、2/5を確認できる。
- キーボード／コントローラーでゲームを操作できる。
- Esc、F11、Alt+F4、Alt+Tab、Windowsキー、Ctrl+O、Ctrl+S、Ctrl+Pなどを試し、
  意図しないデスクトップ、別アプリ、ファイル画面へアクセスできないか確認する。
- Ctrl+Alt+Deleteなどで認証画面へ移る場合も、普段のアカウントへ認証なしに入れない。
- ゲーム内の外部リンクやブラウザーのメニューから制限を抜けられないか確認する。
- ブラウザー終了・クラッシュ後の復旧、PC再起動後の起動順を確認する。
- スタッフが終了・復旧できる。ホスト終了による共有ワールドのリセットも把握する。
- Wi-Fiを両方OFFにして新しく起動し、相互の移動・操作が反映される。
